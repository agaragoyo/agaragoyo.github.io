# 아가라고요

아가라고요는 웹프로그래밍 개론 팀 프로젝트입니다. 2000년대에 유행하던 개인 홈페이지를 "진짜 집 꾸미기"로 바꿔 보자는 생각에서 출발했습니다.
사이트 전체가 옛날 컴퓨터 한 대처럼 생겼고, 전원 버튼을 누르면 부팅과 로그인을 거쳐 바탕화면이 뜹니다.
방 꾸미기와 미니게임은 그 컴퓨터에 깔린 앱이고, 꾸민 방은 링크로 친구에게 보여 줄 수 있습니다.

지금 배포된 모습은 https://agaragoyo.github.io/ 에서 볼 수 있습니다.
모니터 위의 스위치로 1998, 2005, 2010 세 시대의 모습을 바꿔 볼 수 있는데, 어느 시대로 갈지는 팀에서 정하는 중입니다.

## 내 컴퓨터에서 열어 보기

이 사이트는 npm이나 빌드 도구 없이 HTML, CSS, JS 파일 그대로 돌아갑니다. 다만 `index.html`을 더블클릭해서 열면
브라우저가 JS 모듈을 막아서 빈 화면이 나오기 때문에, 작은 로컬 서버를 띄워서 엽니다. 파이썬만 깔려 있으면 됩니다.

```bash
python tools/serve.py
```

그다음 브라우저에서 http://localhost:8123 을 엽니다. 파일을 고치고 새로고침하면 바로 반영됩니다.
`python -m http.server`로 띄우면 브라우저가 예전 JS를 붙잡고 있어서 고친 내용이 안 보일 수 있으니, 꼭 `tools/serve.py`를 씁니다.

## 작업을 올리는 방법

main 브랜치는 배포되는 사이트와 같습니다. 그래서 누구도 main에 바로 올리지 않고, 바꾼 내용을 Pull Request(PR)로 보내 합쳐 달라고 요청합니다.
PR은 김수민이나 전유빈이 확인하고 합칩니다. 레포 설정상 내 PR의 합치기 버튼이 눌리더라도, 직접 합치지 말고 확인을 기다려 주세요.
합쳐지면 1~2분 뒤 사이트에 자동으로 반영됩니다.

무엇을 올리느냐에 따라 방법이 셋으로 나뉩니다. 코드를 고친다면 프로그램을 깔고 내 컴퓨터에서 확인해야 하지만,
그림이나 소리 파일만 넣거나 써 보고 의견만 낼 때는 아무것도 깔지 않고 GitHub 웹 페이지에서 끝낼 수 있습니다.
한 사람이 여러 경우에 걸치면, 예를 들어 게임을 만들면서 그 게임의 그림도 넣는다면 코드를 고칠 때의 방법으로 같이 올리면 됩니다.

### 코드를 고칠 때

미니게임, 기능, 화면 모양처럼 코드를 고칠 때는 내 컴퓨터에 레포를 받아서 작업합니다.
git 명령어가 낯설다면 [GitHub Desktop](https://desktop.github.com/)으로 해도 됩니다. 로컬 서버를 띄우려면 파이썬도 있어야 합니다.

1. 레포를 내 컴퓨터로 받습니다(GitHub Desktop의 Clone repository).
2. 작업을 시작하기 전에 main을 최신으로 받고(Fetch origin, Pull), 새 브랜치를 만듭니다. 이름은 `내아이디/주제`로 짓습니다(예: `soomin007/sand-dig`).
3. 파일을 고치고 로컬 서버에서 확인한 다음 커밋합니다. 커밋 메시지에는 무엇을 왜 바꿨는지 한국어로 한 줄 씁니다.
4. Push origin으로 올리고 Create Pull Request를 누릅니다. PR 설명 칸에 나오는 질문에 답을 채웁니다.
5. 수정 요청이 오면 같은 브랜치에서 고쳐 다시 Push하면 PR에 이어서 붙습니다.

여러 사람이 같은 파일을 동시에 고치면 합칠 때 충돌이 납니다. 미니게임처럼 내 폴더 안에서 끝나는 작업은 충돌이 거의 없지만,
`style.css`나 `src/` 아래 파일처럼 모두가 쓰는 파일을 크게 고칠 때는 단톡방에 미리 말해 주세요.

### 그림이나 소리 파일만 넣을 때

가구 그림, 아이콘, 배경처럼 파일만 넣을 때는 GitHub 웹 페이지에서 바로 올립니다. 아무것도 깔지 않아도 됩니다.

1. 레포 페이지에서 파일이 들어갈 폴더로 들어갑니다. 가구 그림이라면 `assets/furniture`입니다.
2. 오른쪽 위의 **Add file**에서 **Upload files**를 고르고, 파일을 화면에 끌어다 놓습니다.
3. 아래쪽 칸에 무엇을 올렸는지 한 줄 적고 **Propose changes**를 누릅니다. main이 보호되어 있어서 GitHub이 새 브랜치를 알아서 만들어 줍니다.
4. 다음 화면에서 **Create pull request**를 누르면 끝입니다.

파일 이름이 틀리면 사이트가 그림을 찾지 못하니 이름 규칙을 꼭 지켜 주세요. 가구 그림은 `가구id.png`이고,
돌려 놓은 모습은 `가구id-r.png`입니다(돌린 그림이 없으면 원래 그림을 좌우로 뒤집어 씁니다).
가구 id는 `data/furniture.js`에 있는 영어 이름입니다(예: `desk`). 그림 크기와 각도는 아트 방향이 정해지면 따로 정합니다.

### 써 보고 의견을 낼 때

https://agaragoyo.github.io/ 에서 직접 써 보고, 버그나 아이디어는 레포 위쪽의 **Issues** 탭에 남깁니다.
**New issue**를 누르면 "버그 제보"와 "아이디어" 양식이 나오고, 칸을 채우기만 하면 됩니다.
단톡방에 쓰면 금방 흘러가 버리지만 Issues에 남기면 목록으로 쌓이고, 고친 PR과 연결해서 닫을 수 있습니다.
Issues도 누구나 볼 수 있는 곳이니, 팀 안의 이야기는 지금처럼 단톡방에서 나눕니다.

## 어디를 고치면 되나

미니게임이나 새 앱을 만든다면 `apps/README.md`부터 읽으면 됩니다. 앱은 `apps/` 폴더 안의 독립된 웹 페이지라서,
아가라고요의 나머지 코드를 몰라도 HTML 파일 하나로 만들 수 있습니다. 가구 목록은 `data/furniture.js`, 앱 목록은 `data/apps.js`에 있습니다.
모니터와 화면 모양은 `index.html`과 `style.css`가 맡고, 컴퓨터 안의 동작(부팅, 창, 방 꾸미기)은 `src/` 폴더에 있습니다.
파일마다 맡은 일은 `AGENTS.md`의 "구조"에 한 줄씩 정리해 두었습니다.

## AI와 같이 작업할 때

Claude Code, Codex, Cursor 같은 AI 코딩 도구는 레포의 `AGENTS.md`를 스스로 읽고 우리 규칙을 따릅니다.
웹 채팅(ChatGPT, Claude 웹 등)에 코드를 맡길 때는 `AGENTS.md` 내용을 먼저 붙여 넣고 시작하면 됩니다.
AI가 만든 코드도 내가 만든 코드와 똑같이, 로컬 서버에서 직접 눌러 보고 나서 올립니다.

## 기록 남기기

작업 한 덩어리를 마치면 `worklog/` 폴더에 작업 일지를 한 편 써서 같은 PR에 넣습니다. 쓰는 형식은 `worklog/README.md`에 있습니다.
나중에 누가 그 코드를 고칠 때 왜 그렇게 만들었는지 알 수 있게 하려는 기록이라, 몇 줄이면 충분합니다.
같은 실수가 다시 생길 만한 함정을 찾았다면 `known-issues.md`에도 한 항목을 추가합니다. 코드를 고치기 전에 이 파일을 한 번 훑어보면 같은 함정에 빠지지 않습니다.

이 레포는 누구나 볼 수 있는 공개 레포입니다. 일지와 커밋 메시지, PR 설명에는 공개해도 괜찮은 작업 이야기만 쓰고,
팀원에게 물어볼 것이나 팀 안의 이야기는 단톡방에서 나눕니다.
