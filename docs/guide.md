# 아가라고요 설명서

이 글은 코드를 읽지 않고도 아가라고요가 어떻게 생겼고 왜 이렇게 만들었는지 알 수 있도록 쓴 설명서입니다.
내 컴퓨터에서 여는 법과 작업을 올리는 순서는 `README.md`에 있습니다. AI 도구에게 주는 규칙은 `AGENTS.md`, 어떤 파일이 어디에 있는지는 `docs/file-map.md`에 따로 정리했습니다.
무엇을 만들지는 `docs/requirements.md`, 할 일과 담당은 `docs/tasks.md`, 올리기 전에 확인할 것은 `docs/checklists.md`에 있습니다.

## 사이트 전체가 옛 컴퓨터 한 대

아가라고요에 들어오면 웹페이지 대신 옛날 모니터 한 대가 보입니다. 화면은 꺼져 있어서 오른쪽 아래 전원 버튼을 눌러야 켜집니다.
전원을 켜면 하얀 가로선이 퍼지며 화면이 들어오고 부팅 화면을 지나 사용자를 고르는 로그인 화면이 뜹니다.
처음 온 사람은 닉네임을 정해 새 사용자를 만듭니다. 그다음부터는 자기 이름만 누르면 바탕화면으로 들어갑니다.
로그인 화면에는 이웃집도 사용자처럼 늘어서 있어서, 사용자를 만들기 전에 다른 사람이 꾸민 방을 손님으로 구경할 수 있습니다(아래 "이웃집에 놀러 가기").
닉네임 칸을 비운 채 확인을 누르면 칸이 빨갛게 둘러지고 그 아래에 "닉네임을 입력해 주세요."라는 노란 풍선이 뜹니다.

모니터는 그림 파일이 아니라 CSS로 그리고, 크기는 자바스크립트가 화면에 맞춰 정합니다.
그래서 자바스크립트를 다 받을 때까지는 페이지와 같은 색의 가림막이 화면을 덮고 있다가, 모니터가 다 그려지고 글꼴까지 오면 걷힙니다.
자바스크립트는 스무 개가 넘는 파일로 나뉘어 있어서, 브라우저는 파일 하나를 받아 읽어야 그다음에 받을 파일을 알게 됩니다.
배포한 사이트에서는 `tools/stamp.py`가 받을 파일 목록을 `index.html`에 미리 적어 두기 때문에 크롬 계열 브라우저는 처음부터 한꺼번에 받습니다.
사파리는 미리 받다 실패한 파일을 새로 고침해도 다시 받지 않는 버그가 있어서 예전처럼 차례로 받습니다.
글꼴도 첫 화면에는 갈무리 전체(약 670KB) 대신, 갈무리에서 사이트가 쓰는 글자만 남긴 작은 글꼴 AgaUI(약 21KB)를 씁니다.
가림막은 이 작은 글꼴만 기다리고, 사용자가 치는 닉네임이나 말풍선처럼 작은 글꼴에 없는 글자는 가림막이 걷힌 뒤에 이어 받는 갈무리 전체가 그립니다.
연결이 느려 1초가 넘게 걸리면 가운데에 작은 점 세 개가 깜빡이고, 10초가 넘으면 새로 고침 단추도 나옵니다.

바탕화면에는 방 꾸미기, 놀이터, 미니게임 폴더, 공유하기, 마우스 아이콘이 있습니다. 아이콘을 두 번 누르면 창이 열리고
(놀이터 아이콘만은 창 대신 바탕화면을 놀이터로 옮깁니다), 창은 끌어서 옮기거나 최소화, 최대화, 닫기를 합니다. 아래 작업 표시줄에는 열린 창이 버튼으로 늘어섭니다.
시작 버튼을 누르면 앱 목록과 함께 불 끄기, 튜토리얼 다시 보기, 로그아웃, 컴퓨터 끄기가 나옵니다.

굳이 컴퓨터 모양을 만든 까닭은 2000년대 개인 홈페이지의 느낌을 살리고 싶었기 때문입니다.
그때 홈페이지는 꾸미는 공간이면서 친구가 놀러 오는 공간이었고, 그 경험은 대개 집에 있던 컴퓨터 한 대에서 일어났습니다.
그래서 방 꾸미기와 미니게임을 따로 된 페이지가 아니라 그 컴퓨터 안의 프로그램으로 만들었습니다.

## 2005년 모습

화면은 은색 평면 브라운관 모니터에 파란 창과 초록 시작 버튼을 쓰는 2005년 무렵의 컴퓨터로 보여 줍니다. 부팅할 때는 검은 화면에 로고와 진행 막대가 나옵니다.
처음에는 1998(베이지색 볼록 브라운관), 2005, 2010(검은 와이드 모니터) 세 시대를 모두 만들어 팀과 11주차 알파 테스트에서 비교했고,
2026년 11월 10일 2005로 정해 나머지 두 모습은 지웠습니다. 모양은 `style.css` 끝의 "2005 모습" 절에 모여 있습니다.
실제 윈도우의 로고나 이름은 쓰지 않습니다. 시작 버튼의 로고는 우리 개념에 맞춰 작은 집으로 그렸고,
부팅 화면과 커서도 그 시절 분위기만 따랐을 뿐 모두 새로 그린 그림입니다.

## 내 방 꾸미기

방 꾸미기를 열면 비스듬히 내려다보는 방이 나옵니다. 왼쪽 벽, 오른쪽 벽, 마름모 바닥으로 된 이 시점은 예전 미니룸처럼 아이소메트릭이라고 부릅니다.
위쪽 탭으로 내 방과 놀이터를 오가고, 화면 아래 선반에는 지금 공간에 놓을 수 있는 가구가 늘어서 있습니다.
방 꾸미기는 바탕화면에 보이는 공간의 탭부터 열리므로, 놀이터에 나가 있을 때 열면 놀이터부터 꾸미게 됩니다.
방 꾸미기 창은 하나뿐이라 이미 열려 있으면 고르던 탭 그대로 앞으로 나옵니다.

선반의 가구를 끌어다 방에 놓으면 격자에 맞춰 자리를 잡습니다. 다른 가구와 겹치거나 벽 밖으로 나가는 자리에서는 빨갛게 표시되고 놓이지 않습니다.
놓은 가구는 다시 끌어 옮기고, 선반 위로 끌어다 놓으면 치워집니다. 바닥 가구와 책상 위 물건은 끄는 동안 R 키나 마우스 휠로 돌립니다.
1인 소파처럼 칸이 정사각형인 가구도 돌아갑니다. 차지하는 칸은 그대로이고 그림만 좌우로 뒤집혀 다른 쪽을 봅니다. 벽에 거는 가구는 돌리지 않습니다.
컴퓨터나 머그컵처럼 작은 물건은 책상 위에 올라가고, 책상을 옮기면 위에 있던 물건도 함께 따라옵니다.

꾸민 방은 곧바로 이 컴퓨터에 저장됩니다. 바탕화면 배경도 내가 꾸민 방 그림이라서, 방을 고치면 바탕화면이 같이 바뀝니다.
가구 그림이 아직 없는 동안에는 가구마다 정해 둔 색의 상자로 보이고, 그림 파일이 들어오면 그 그림으로 바뀝니다.
가구 그림은 전원을 켤 때 로그인 화면에서 고를 수 있는 집(내 집, 링크로 온 친구 집, 이웃집)에 놓인 것부터 받기 시작해서,
바탕화면이 뜰 때는 그림이 있는 가구가 처음부터 그림으로 보입니다(known-issues 54).
그림이 들어온 가구는 그림의 칠해진 부분만 눌리고, 투명한 여백을 누르면 그 뒤의 가구나 바닥이 눌립니다.

## 가구를 누르면 생기는 일

가구는 꾸미는 물건이면서 쓰는 물건이기도 합니다. 바탕화면 배경의 방에서 가구를 두 번 누르면 아바타가 그 가구 옆으로 걸어가고,
도착하면 그 가구에 정해 둔 일이 일어납니다. 이것을 기믹이라고 부릅니다. 지금 들어 있는 기믹은 여덟 가지입니다.
스탠드와 가로등은 밤과 낮을 바꾸고, 컴퓨터는 주인이 넣어 둔 웹 게임을 새 탭으로 열고,
게임기는 미니게임을, 책장은 주인이 꽂아 둔 책을, 라디오는 주인이 넣어 둔 CD를, TV는 주인이 고른 영화와 TV 시리즈를,
코르크 보드는 손님이 붙인 쪽지를 엽니다(코르크 보드는 시험입니다).
밤이 되면 화면이 어두워지면서 불빛 가구 둘레만 환하게 남습니다. 밤은 방의 불을 끈 상태라, 로그인 화면은 밤에도 낮 색 그대로입니다.
한 번 누르기는 바닥을 눌러 걷기와 헷갈리지 않도록 아무 일도 하지 않습니다. 바탕화면 아이콘을 두 번 눌러 여는 것과 같은 약속입니다.

방 꾸미기는 꾸미는 화면이라 가구를 눌러도 기믹을 쓰지 않고, 바탕화면에서 두 번 눌러 보라는 안내만 뜹니다.
처음에는 바탕화면이 아이콘을 누르는 곳이라 누르기의 뜻이 겹친다고 보고 기믹을 방 꾸미기에서 썼습니다. 아바타가 바탕화면에 살게 되면서
심즈의 생활 모드처럼 지내는 화면에서 쓰고, 꾸미는 화면에서는 옮기기만 하도록 나눴습니다.

옛날 홈페이지의 즐겨찾기 링크가 하던 일은 가구가 맡습니다. 주인은 내 컴퓨터에서 가구를 두 번 눌러 뜬 화면에서 좋아하는 것을 넣어 둡니다.
컴퓨터라면 좋아하는 웹 게임의 주소를 넣고, 그 뒤로는 누가 컴퓨터를 쓰든 그 게임이 어느 사이트의 새 탭에서 열리는지 먼저 보여 준 다음 엽니다.
넣은 것은 집 상태의 `likes`에 가구마다 한 칸씩 저장되고 공유 링크에도 담기므로, 손님도 같은 가구를 눌러 주인이 넣어 둔 것을 봅니다.
손님 화면에는 넣거나 고치는 단추가 없고, 아무것도 넣지 않은 가구를 손님이 쓰면 아바타가 "넣어 둔 게임이 없네."처럼 한마디 합니다.
주인이 넣은 글과 주소는 남의 화면에서 그대로 보이므로, 글은 글자로만 넣고 주소는 http나 https로 시작하는 것만 받습니다(`src/likes.js`).

게임기처럼 손에 들고 보는 가구는 창 대신 "가까이 보기" 화면으로 엽니다(`src/closeup.js`). 바탕화면이 어둡게 가려지고 가운데에 가구가 크게 뜨며,
가구 바깥의 어두운 곳이나 아래의 닫기 단추, Esc를 누르면 닫힙니다. 닫기 단추는 가구에 맞는 말로 써서, 손에 드는 게임기는 "내려놓기", TV는 "TV 끄기",
라디오와 책장은 "닫기"입니다(라디오는 닫아도 음악 창이 남으므로 "끄기"라고 쓰지 않습니다). 보는 동안 방향키는 아바타 대신 그 가구가 받습니다.
게임기 화면에는 미니게임 폴더의 게임이 늘어섭니다. 게임기의 단추는 셋이고, 단추 아래에 하는 일을 새겨 두었습니다. 십자 단추(방향키)는 고르기, A(Enter)는 시작,
B(Backspace)는 나가기입니다. 게임이나 새 탭 안내에서 B를 누르면 게임기 첫 화면으로 돌아오고, 첫 화면에서 누르면 게임기를 내려놓습니다. 게임 안의 그만하기 단추도 첫 화면으로 돌아옵니다.
처음에는 실제 휴대용 게임기처럼 단추를 넷 두었는데, 아무 일도 하지 않는 장식 단추는 무슨 역할인지 알 수 없어서 뺐습니다.
새 탭으로 여는 플래시 게임은 게임기 화면 안에서 어느 사이트로 가는지 먼저 보여 줍니다.
주인은 칸마다 붙은 별을 눌러 추천 게임 하나를 고를 수 있고, 추천 게임은 손님의 게임기에서도 맨 앞에 "추천" 표시를 달고 섭니다.

책장에는 책을 다섯 권까지 꽂습니다. 주인이 책 제목과 작가, 좋아하는 구절이나 고른 이유를 쓰면, 모든 책이 같은 디자인인 표지의 이름표 자리에 제목과 작가가 들어가고
책 색은 여덟 가지 가운데 무작위로 정해집니다(바로 앞 책과 같은 색은 피합니다). 책장을 열면 고른 책의 표지와 남긴 말이 크게 뜨고,
아래 선반의 책등을 누르거나 ←, → 방향키로 옆 책을 봅니다. 주인에게는 "고치기", "이 책 빼기" 단추와 선반의 빈 자리(+)가 있어 책을 고치거나 더 꽂습니다.

라디오에는 Spotify나 Apple Music의 앨범, 플레이리스트 공유 링크를 CD로 여섯 장까지 넣습니다. 라디오를 열면 CD가 위에 펼쳐지고, 하나를 고르면 그 CD가 라디오의 CD 창으로 들어가
재생 단추가 눌린 뒤 돌기 시작합니다. 그러면 그 서비스의 공식 플레이어가 바탕화면 오른쪽 위의 작은 창에 뜨고, 라디오는 왼쪽으로 비켜 섭니다.
미리 듣기 길이는 서비스가 정해서, 로그인하지 않은 사람은 노래마다 30초쯤, 그 서비스에 로그인한 사람은 끝까지 듣습니다.
음악 창은 라디오를 내려놓아도 남아 있어 방을 걸으며 들을 수 있고, 창이 열려 있는 동안 사이트 배경음악은 멈춥니다. ■나 창의 닫기를 누르면 음악이 멈춥니다.
다른 CD를 고르면 라디오에 든 CD와 바뀌고, ■ 옆의 꺼내기 단추(⏏ 모양)를 누르면 음악이 멈추고 CD가 펼친 자리로 돌아갑니다.
라디오에 든 CD의 자리는 점선 동그라미로 남아서 CD가 한 장뿐이어도 펼친 줄이 비지 않습니다.
주인이 CD를 목록에서 지우는 단추는 꺼내기와 헷갈리지 않게 "이 CD 지우기"라고 씁니다.
주인이 넣은 링크를 그대로 창에 띄우지 않고, 링크에서 앨범이나 플레이리스트의 id만 알아본 뒤 공식 플레이어 주소를 새로 만들어 띄웁니다.
CD에 깔리는 앨범 표지와 이름은 볼 때마다 서비스의 공개 정보(Spotify oEmbed, iTunes 조회)에서 받아 오므로 API 키가 필요 없습니다.

TV 화면에는 주인이 고른 영화와 TV 시리즈의 포스터가 넷플릭스의 추천 줄처럼 한 줄로 늘어섭니다. 휠을 굴리거나 ←, → 방향키로 넘기고,
고른 작품의 이름과 연도, 감독, 추천 이유가 아래에 뜹니다. 링크가 있으면 "새 탭에서 보기" 옆에 열리는 사이트 이름이 같이 나옵니다.
주인이 작품을 넣을 때는 먼저 이름으로 찾습니다. 찾기는 API 키가 필요 없는 위키데이터를 써서, "2019년 봉준호 감독의 영화"처럼 연도와 감독이 붙은 목록이 나오고,
고르면 이름, 연도, 감독, 위키백과 링크가 채워집니다. 찾는 방법은 둘을 합칩니다. 먼저 한국어 이름, 원제, 별칭에서 정확히 같거나 앞부분이 같은 이름을 찾아
설명으로 작품만 남깁니다. "It", "Up"처럼 짧은 원제나 "기생"처럼 앞부분만 친 이름도 이것으로 찾습니다. 8편이 안 되면 영화, 애니메이션, 드라마 같은 작품으로 분류된 문서에서
낱말로 찾아 많이 알려진 순서로 채웁니다(`src/apps/tv-app.js`의 `searchWorks`, `WORK_TYPES`). 같은 이름의 방송국이나 음반, 시즌 하나만 가리키는 문서는 빠집니다.
이름은 넷플릭스와 왓챠의 한국판처럼 한국어 이름(한국 개봉 제목)을 쓰고, 찾은 목록에는 원제를 함께 보여 줍니다. 넣는 칸에서 이름을 원제로 고쳐도 됩니다.
링크는 넷플릭스 주소처럼 다른 곳으로 고칠 수 있고, 목록에 없는 작품은 "직접 넣기"로 넣습니다.
포스터는 주인이 그림 주소를 붙여 넣습니다. 넣지 않으면 책 표지처럼 색 카드의 이름표 자리에 제목과 연도를 쓴 카드가 걸립니다. 작품은 여섯 편까지 넣습니다.

코르크 보드는 다른 가구와 반대로 주인이 아니라 손님이 채우는 방명록입니다(시험, 요구 사항 F22). 보드를 열면 나무 틀 안의 코르크 판에
손님이 붙인 쪽지가 최근 것부터 열두 장씩 포스트잇처럼 붙어 있고, 더 오래된 쪽지는 "지난 쪽지"로 넘겨 봅니다.
손님은 "쪽지 남기기"를 눌러 포스트잇 색 네 가지 가운데 하나를 고르고, 닉네임(12자)과 남길 말(60자)을 쓴 뒤 Enter나 "붙이기"로 붙입니다.
닉네임 칸에는 그 브라우저로 마지막에 쓴 닉네임이, 없으면 그 컴퓨터에 사는 사람의 닉네임이 미리 들어갑니다. 손님끼리도 서로의 쪽지를 읽습니다.
주인에게는 쓰는 단추가 없고 모든 쪽지에 지우기 단추가 있습니다. 손님은 같은 브라우저로 붙인 자기 쪽지만 지울 수 있고,
지우기를 누르면 쪽지 위에 "이 쪽지를 지웁니다. 되돌릴 수 없습니다."와 "지우기", "그대로 두기" 단추가 뜹니다.
쪽지는 서버에 있어서 주인이 짧은 링크를 만든 방에서만 쓰입니다. 짧은 링크가 없는 주인이 보드를 열면 짧은 링크를 만들면 친구가 쪽지를 남길 수 있다는 안내와
공유하기를 여는 단추가 뜨고, 긴 링크로 온 손님에게는 그 링크로는 쪽지를 남길 수 없으니 주인에게 짧은 링크를 받아 달라는 안내가 뜹니다.
주인이 내 컴퓨터로 들어올 때 마지막으로 보드를 본 뒤 새 쪽지가 붙었으면 "코르크 보드에 새 쪽지가 있습니다."를 알려 줍니다.
이 방식은 비슷한 서비스 네 곳을 보고 정했습니다. 동물의 숲(New Horizons)은 친구 섬의 게시판에도 글을 남길 수 있고, 섬 주민과 손님의 글이 한 게시판에 같이 보이며, 쓴 사람이 자기 글을 지웁니다.
패들렛은 글을 쓴 사람과 보드 주인이 글을 지웁니다. '내 트리를 꾸며줘'는 가입 없이 링크로 메시지를 달게 하되 내용은 주인에게만 보여 줍니다.
싸이월드 방명록은 손님이 남긴 글에 주인이 답글을 달며 오가는 곳이었습니다. 그래서 링크만 있으면 가입 없이 쓰고, 손님끼리도 읽고, 나쁜 쪽지는 주인이 지우게 했습니다.
주인의 답글은 넣지 않았습니다. 쪽지를 고칠 수 없게 막아 둔 규칙을 풀어야 하기 때문입니다. 보드 그림은 아직 없어서 방에서는 코르크색 상자로 보입니다.

아직 기믹이 없는 가구는 아바타가 다가가 "옷장이네."처럼 가구 이름을 말합니다. 냉장고를 두 번 누르면 요리 게임이 열리는 식의 기믹은
팀원이 앱으로 만들어 그 가구에 연결하면 됩니다. 앱 목록에 한 줄, 가구 목록에 한 줄을 더하는 일이라 OS 코드를 고칠 필요가 없습니다.

## 방 안을 걷는 아바타

내 아바타는 바탕화면 배경의 방에 삽니다. 로그인하면 바닥 앞쪽 가운데에 서 있고, 바닥을 누르면 가구를 피해 그 칸까지 걸어갑니다.
앞에 고른 창이 없을 때는 방향키나 WASD로 한 칸씩 걸을 수도 있습니다. 창을 쓰다가 바탕화면을 누르면 모든 창이 뒤로 물러나고, 그때부터 키는 아바타가 받습니다.
방이 45도 돌아가 보이므로 ↑는 오른쪽 위, →는 오른쪽 아래, ↓는 왼쪽 아래, ←는 왼쪽 위로 걷습니다.
Enter를 누르거나 아바타를 누르면 작업 표시줄 위에 입력 칸이 뜨고, 쓴 말은 머리 위 말풍선으로 몇 초 동안 떠 있습니다.
Ctrl, Cmd, Alt와 함께 누른 키는 브라우저 단축키로 남겨 두어서, 그때는 아바타가 움직이지 않습니다.

아바타는 1×1칸짜리 움직이는 가구처럼 가구와 앞뒤를 맞춰 그립니다. 앞뒤는 화면에서 아바타 그림과 겹치는 가구끼리만 따지고,
걷는 동안에는 지나는 두 칸을 합친 자리로 따집니다. 겹치지 않는 먼 가구까지 세면 아바타가 바로 앞 가구의 위에 그려져
가구를 뚫고 다니는 것처럼 보입니다(known-issues 53).

아바타는 놀이터에도 나갈 수 있습니다. 방 왼쪽 벽의 현관문을 두 번 누르면 아바타가 문 앞으로 걸어간 뒤 바탕화면이 놀이터로 바뀌고,
아바타는 울타리의 아파트 문으로 막 들어온 자리에 섭니다. 바탕화면의 놀이터 아이콘을 두 번 누르면 걷지 않고 곧장 놀이터로 갑니다.
돌아올 때는 놀이터 울타리의 "아파트" 문을 두 번 누릅니다. 아바타가 문 앞까지 걸어간 뒤 내 방의 현관문 앞으로 돌아오고, 로그인할 때는 늘 내 방에서 시작합니다.
현관문은 가구가 아니라 방 그림의 일부라 늘 같은 자리에 있고, 방 꾸미기에서는 그 자리에 벽 가구를 걸 수 없습니다.
현관문은 2026-11-10에 시험으로 넣었고, 그전에는 창문을 두 번 눌러 나갔습니다. 그때 현관문 자리에 걸어 둔 창문은 불러올 때 사라지지 않고 남습니다.
놀이터에 있는 동안에는 바탕화면의 놀이터 아이콘이 집으로 아이콘으로 바뀌므로, 가구로 문을 가려 두어도 곧장 돌아올 수 있습니다.

바탕화면은 지내는 화면이고 방 꾸미기는 꾸미는 화면입니다. 그래서 방 꾸미기 창에는 아바타가 나오지 않습니다. 가구를 놓는 데 걸리적거리지 않게 하려는 것으로,
심즈의 건축 모드나 동물의 숲의 꾸미기 모드처럼 꾸미는 동안에는 캐릭터를 비켜 두는 방식을 따랐습니다.
아바타가 서 있던 칸에 가구를 놓으면, 바탕화면으로 돌아왔을 때 아바타는 가장 가까운 빈칸으로 비켜섭니다.

아바타는 한 칸짜리 움직이는 가구처럼 다룹니다. 가구와 같은 상자에 그려서, 가구보다 앞에 서면 가구 위에, 뒤에 서면 가구 아래에 보입니다.
바탕화면 배경 안에 있으므로 창이 열려 있으면 그 창 뒤로 지나갑니다. 키가 큰 가구 뒤에 가려진 칸은 방향키로 걸어 들어갑니다.

지금은 1단계라 아바타가 내 화면에서만 움직입니다. 친구 집에 놀러 가도 내 아바타는 다른 사람에게 보이지 않고, 말풍선도 저장되지 않습니다.
아바타 그림은 아직 코드로 그린 임시 그림입니다. 아트 팀이 그릴 그림은 한 칸이 64×104px이고, 가로 3칸(서 있기, 왼발, 오른발)과 세로 2줄(앞모습, 뒷모습)을 한 장(192×208px)에 모읍니다.
자세한 규격은 `data/avatars.js` 맨 위에 있습니다.

## 처음 온 사람을 위한 튜토리얼

새 사용자를 만들고 바탕화면에 처음 들어오면 화면 오른쪽 아래에 작은 노란 안내 카드가 뜨고, 화살표가 지금 눌러야 할 곳을 가리킵니다.
카드는 한 번에 한 가지만 부탁합니다. 방 꾸미기를 열고, 선반의 침대와 스탠드를 끌어다 바닥에 놓은 뒤 창을 닫습니다.
그다음 바탕화면의 방에서 스탠드를 두 번 눌러 밤으로 바꿨다가 낮으로 되돌리고, 방 벽의 현관문을 두 번 눌러 놀이터로 나간 뒤 울타리의 아파트 문을 두 번 눌러 돌아옵니다.
침대로는 가구를 놓는 법을, 스탠드로는 가구를 쓸 수 있다는 것을, 현관문으로는 놀이터가 있다는 것을 배우는 순서입니다. 놓은 가구는 그대로 내 방에 남습니다.
2026-11-10까지는 창문도 벽에 걸고 창문으로 놀이터에 나갔습니다.

카드에는 "다음" 단추가 없습니다. 사용자가 부탁받은 일을 하면 카드가 저절로 다음 단계로 넘어갑니다.
튜토리얼은 몇 단계까지 했는지를 저장하지 않고, 방의 가구와 열린 창, 공간, 밤낮을 계속 읽어 아직 하지 않은 첫 단계를 고릅니다.
그래서 스탠드를 먼저 놓아도 괜찮고, 놓았던 침대를 선반으로 치우면 침대 단계로 돌아오고, 중간에 새로 고침을 해도 이어집니다.
가구가 겹치는 빨간 자리로 끌면 카드에 놓을 수 없다는 안내가 그동안만 보입니다.

카드의 "건너뛰기"를 누르면 튜토리얼이 끝나고 다시 나오지 않습니다.
튜토리얼은 새 사용자를 만들 때만 저절로 시작합니다. 예전부터 쓰던 사용자와 공유 링크로 들어온 손님에게는 나오지 않습니다.

시작 메뉴의 "튜토리얼 다시 보기"를 누르면 지금 방은 그대로 두고 빈 방에서 연습한다는 안내 창이 먼저 뜹니다. 열려 있는 창이 있으면 그 창들이 닫힌다는 것도 함께 적습니다.
"빈 방에서 연습하기"를 누르면 가구가 하나도 없는 낮의 연습 방에서 첫 단계부터 끝까지 해 볼 수 있습니다.
튜토리얼이 지금 상태를 읽어 단계를 고르기 때문에, 침대가 이미 있는 방에서 다시 시작하면 놓는 단계가 저절로 지나갑니다. 그래서 저장된 방을 지우는 대신 빈 방을 잠시 빌려 씁니다.
연습 방에 놓은 가구와 바꾼 밤낮은 메모리에만 있고 저장되지 않습니다. 연습 중에 공유하기를 열면 연습 방이 아니라 저장된 내 방이 링크와 PNG에 담깁니다.
카드의 "내 방으로 돌아가기"를 누르면 언제든 저장된 방으로 돌아옵니다. 로그아웃, 전원 끄기, 새로 고침을 해도 연습은 끝나고 저장된 방과 밤 설정이 그대로 남습니다.
처음 튜토리얼을 하던 중에 다시 보기를 눌렀다면, 연습이 끝난 뒤 하던 자리에서 이어집니다.

이렇게 만든 것은 다른 게임과 제품이 첫 경험을 어떻게 가르치는지 살펴본 결과입니다. 포털이나 슈퍼 마리오의 첫 스테이지는 글로 설명하지 않고,
위험이 없는 곳에서 한 번에 한 가지를 직접 해 보게 합니다. 닐슨 노먼 그룹은 앱을 열자마자 보여 주는 설명은 금방 잊힌다고 보고, 필요한 순간에 띄우는 도움말을 권합니다.
그래서 설명 화면을 먼저 보여 주지 않고, 그 행동을 할 차례가 왔을 때 그 자리를 가리킵니다. 심즈의 첫 튜토리얼은 잘못할 수 있는 일이 거의 없다고 말해 주고,
동물의 숲의 첫날은 작은 일들을 하며 곧장 내 섬을 시작합니다. 우리 튜토리얼도 틀렸다고 막는 일 없이, 처음에는 진짜 내 방에서 진행합니다.

튜토리얼에 쓰는 가구는 `data/furniture.js`의 `TUTORIAL_FURNITURE` 한곳에서 바꿉니다. 가구별 인터랙션이 정해지면 침대는 다른 가구로 바뀔 수 있고, 안내 문구의 가구 이름은 저절로 따라갑니다.

## 저장과 공유

내 방은 지금 쓰는 브라우저 안(localStorage)에 저장됩니다. 그래서 다른 컴퓨터나 다른 브라우저에서 열면 내 방이 보이지 않습니다.
서버는 친구에게 보내는 짧은 링크와 코르크 보드의 쪽지에만 씁니다.

친구에게 방을 보여 줄 때는 공유하기 앱에서 링크를 복사해 보냅니다. 링크로 들어온 친구가 로그인 화면에서 "손님으로 구경하기"를 고르면,
그 방이 배경인 바탕화면에 손님의 아바타가 들어섭니다. 가구를 옮기지는 못해도 방을 걸어 다니며 가구를 두 번 눌러 기믹을 찾는 재미는 똑같이 누립니다.
손님의 바탕화면에는 방 꾸미기와 공유하기 아이콘 대신, 이 컴퓨터에 내 집이 없으면 "나도 만들기", 있으면 "내 컴퓨터로" 아이콘이 있습니다.
나도 만들기를 두 번 누르면 로그인 화면으로 가서 자기 사용자를 만들 수 있고, 내 컴퓨터로를 두 번 누르면 로그인 화면을 거치지 않고 곧장 내 바탕화면으로 돌아갑니다.

링크는 두 가지입니다. 긴 링크는 `https://agaragoyo.github.io/#r=` 뒤에 방을 통째로 담은 글자를 붙인 꼴이라 서버 없이 열립니다.
카카오톡은 메시지를 500자까지만 보여 주고 나머지를 접어서, 가구 하나를 가구 번호와 자리 2바이트로 담는 짧은 형식으로 만듭니다(`src/share.js`).
가구 22개를 놓고 책 한 권을 담은 방은 175자이지만, 가구에 책 메모나 TV 작품처럼 글을 많이 담으면 그 글이 링크에 그대로 실려 500자를 넘깁니다.
방을 고친 뒤에는 긴 링크를 다시 복사해야 바뀐 모습이 전해집니다. 2026-11-11 전에 만든 `#room=` 링크도 그대로 열립니다.
가구 번호는 `src/share.js`의 `LINK_CODES` 순서라서, 새 가구는 그 끝에만 더합니다(순서를 바꾸면 이미 보낸 링크의 가구가 바뀝니다).

짧은 링크는 `https://agaragoyo.github.io/#s=` 뒤에 방 번호 여덟 글자를 붙인 꼴이고 39자입니다(시험, 요구 사항 F21).
공유하기 창에서 "짧은 링크 만들기"를 누르면 긴 링크에 담던 글자를 서버(Firebase의 Firestore)에 올리고 번호를 받습니다.
그 뒤에는 방을 고칠 때마다 3초 뒤에 서버의 방도 따라 고쳐지므로, 이미 보낸 짧은 링크가 늘 지금 방을 보여 줍니다.
짧은 링크로 온 손님의 브라우저는 부팅 화면이 나오는 동안 서버에서 방을 받아 오고, 로그인하지 않고 읽기만 합니다.
방을 올리고 고치고 지우는 일은 가입 없이 브라우저마다 하나 생기는 익명 사용자로 하고, 서버의 보안 규칙(`firestore.rules`)이 방을 처음 올린 사용자만 고치고 지울 수 있게 막습니다.
그래서 짧은 링크를 만든 브라우저의 저장소를 지우면 그 링크의 방은 더 고칠 수 없습니다.
공유하기 창의 "짧은 링크 지우기"와 로그인 화면의 "이 컴퓨터 초기화"는 서버의 방도 지웁니다. 짧은 링크가 열리지 않는 날에는 같은 창의 "긴 링크 복사"로 긴 링크를 보낼 수 있습니다.

서버 코드는 Firebase SDK 없이 REST 주소를 fetch로 부릅니다(`src/cloud.js`). SDK를 받으면 첫 화면이 무거워지고, SDK가 저장소에 우리 규칙(`agarago.`로 시작)과 다른 이름의 키를 쓰기 때문입니다.
무료 플랜(Spark)이라 하루에 읽기 5만 번, 쓰기 2만 번까지 쓸 수 있고, 넘으면 태평양 시간 자정(한국 시간 오후 4~5시)까지 서버가 막힙니다.
보안 규칙은 레포의 `firestore.rules`를 Firebase 콘솔에 붙여 게시한 것이라 서버에 저절로 올라가지 않습니다. 규칙을 고친 PR을 합친 뒤에는 Admin이 콘솔에 게시합니다(known-issues 59).

코르크 보드의 쪽지는 서버의 방 문서 아래(`homes/{방 번호}/notes/{쪽지 번호}`)에 한 장씩 둡니다. 쪽지 한 장에는 쓴 사람의 익명 사용자 번호, 닉네임, 남길 말, 색 번호, 붙인 시각(서버 시각)만 들어갑니다.
규칙은 서버에 있는 방에만 붙이게 하고, 칸과 글자 수를 검사하며, 붙인 쪽지는 고치지 못하게 막고, 지우기는 쓴 사람과 방 주인에게만 허락합니다.
규칙은 글자를 UTF-16 단위로 세서 이모지 하나를 두 글자로 봅니다. 입력 칸의 글자 수 제한도 같은 단위라 칸이 받은 글은 서버도 받습니다(known-issues 60).
Firestore는 받은 문서마다 읽기를 한 번씩 세므로, 쪽지는 보드를 열 때만 열두 장(남은 쪽지가 있는지 보려고 한 장 더)을 받고 손님에게는 로그인 없이 읽힙니다.
주인이 들어올 때의 새 쪽지 확인은 가장 최근 쪽지 한 장만 읽습니다. 쪽지를 붙이거나 지우는 손님은 가입 없이 익명 사용자가 되어, 같은 브라우저에서는 자기 쪽지를 알아봅니다.
짧은 링크 지우기와 이 컴퓨터 초기화는 방을 지우기 전에 그 방의 쪽지를 먼저 지웁니다. 방이 먼저 없어지면 규칙이 방 주인을 알아보지 못해 남은 쪽지를 지울 수 없기 때문입니다.

링크 대신 그림 한 장으로 보내고 싶다면 같은 공유하기 앱에서 "내 방 그림 PNG로 내려받기"를 누릅니다. 놀이터도 따로 내려받을 수 있습니다.
누르는 순간의 방이 낮 모습 그대로 `agarago-room.png` 같은 파일로 저장되고, 크기는 화면의 방(1280×720px)의 두 배인 2560×1440px입니다. 아바타는 들어가지 않습니다.
화면의 방은 SVG 바탕 위에 가구 상자를 CSS로 겹쳐 놓은 것이라 브라우저가 사진처럼 찍어 주지 못합니다.
그래서 `src/room-image.js`가 화면이 쓰는 함수로 가구의 자리와 앞뒤 순서를 구해 캔버스에 다시 그립니다. 방의 모양을 고쳤다면 내려받은 그림도 같은 모양인지 함께 봐야 합니다.

로그인 화면의 "이 컴퓨터 초기화"는 저장된 집과 게임 기록을 지우고 처음 상태로 돌립니다. 누르면 지울 내용을 먼저 보여 주고, "지우기"를 눌러야 실제로 지웁니다. 그 뒤에 새 사용자를 만들면 튜토리얼도 다시 시작합니다.
밤과 낮, 소리, 배경음악 같은 설정은 컴퓨터 자체의 설정으로 보고 지우지 않습니다.

## 이웃집에 놀러 가기

알파 테스트에서 가장 많이 나온 말은 무엇을 하는 곳인지 모르겠다는 것이었습니다. 처음 온 사람이 빈 방부터 꾸미면, 가구에 좋아하는 것을 담아 친구에게 보여 주는 재미를 알기 어렵습니다.
그래서 팀원이 꾸민 방을 이웃집으로 두고, 처음 온 사람이 채워진 방부터 구경할 수 있게 했습니다. 팀에서 정하기 전에 써 보려고 2026-11-10에 시험으로 넣었습니다(요구 사항 F19).

이웃집은 `data/neighbors.js`에 문패에 쓸 닉네임과 그 집 긴 링크 값을 한 줄씩 적은 것입니다. 이웃집은 서버를 거치지 않고 긴 링크와 같은 방식으로 열리고,
링크 속 가구와 글, 주소는 친구 링크와 똑같은 검사를 거칩니다. 지금은 팀원 방 하나와, 팀원 방이 오기 전에 넣어 둔 시험용 방 "관리인"이 들어 있습니다.
새로 받은 팀원 방은 관리인 앞에 받은 차례대로 더합니다.

로그인 화면에서는 이웃집이 사용자처럼 늘어서고, 누르면 바로 그 집에 손님으로 들어갑니다. 처음 온 사람에게는 이웃집이 새 사용자 만들기보다 위에 있습니다.
친구 링크로 들어왔을 때는 그 친구의 방에 집중하도록 이웃집을 내놓지 않습니다.
놀이터 왼쪽 울타리에는 이웃마다 닉네임을 쓴 나무 문패를 단 문이 있습니다. 두 번 누르면 아바타가 문 앞까지 걸어간 뒤 어느 집에 놀러 가는지 알려 주는 창이 뜨고,
"놀러 가기"를 눌러야 그 집으로 갑니다. 내 집이 있는 사람에게는 돌아오는 길도 같은 창에 한 줄로 알려 줍니다.
이웃집에 놀러 가 있는 동안 그 집 놀이터에는 그 집 문패가 없습니다. 아파트 문이 이미 그 집으로 가는 문이라 같은 곳으로 가는 문이 둘이 되기 때문입니다.
로그인 화면과 놀이터에는 여섯 집까지 나옵니다.
손님 자리에서 돌아오는 길은 앞의 "저장과 공유"에 적은 나도 만들기와 내 컴퓨터로 아이콘입니다.

이 방식은 비슷한 서비스 세 곳을 보고 정했습니다. 싸이월드의 파도타기는 일촌의 이름을 한눈에 늘어놓고 골라서 건너가게 했습니다.
동물의 숲의 꿈 방문은 떠나기 전에 가려는 섬의 이름을 확인받고, 꿈속에서 한 일은 그 섬에 남기지 않습니다.
Gather는 다른 공간으로 가는 문에서만 확인 창을 띄우고, 같은 공간 안의 문은 바로 지나가게 합니다.
그래서 이웃집 이름은 문패와 사용자 줄로 늘어놓고, 다른 컴퓨터로 가는 놀이터 문에서만 묻고, 같은 컴퓨터 안의 현관문과 아파트 문은 묻지 않습니다.
손님은 가구를 옮기지 못하므로 구경하는 동안 이웃집에도 내 집에도 아무것도 바뀌지 않습니다.

이웃집을 더하는 법은 `data/neighbors.js` 맨 위에 있습니다. 링크 속 주인 이름도 문패 닉네임과 같아야 합니다.
링크는 누구나 풀어 읽을 수 있어서, 다른 이름(실명일 수 있습니다)이 공개 레포에 숨어 올라가지 않게 하려는 것입니다. 다르면 자동 점검이 알려 줍니다.

## 앱과 미니게임

미니게임처럼 창 안에 뜨는 프로그램은 저마다 따로 된 작은 웹페이지입니다. 아가라고요는 그 페이지를 창 안에 끼워 보여 줄 뿐이라,
팀원은 다른 사람의 코드를 몰라도 HTML 파일 하나로 자기 게임을 만들고, 서로의 코드가 섞이지도 않습니다.
만드는 동안에는 그 페이지만 브라우저로 열어 확인해도 됩니다.

아가라고요 창 안에서 열린 게임은 작은 연결 도구(SDK)를 빌려 씁니다. 창을 닫거나 창 제목에 최고 점수를 띄우고,
기록을 다른 게임과 섞이지 않게 저장하고, 게임판을 창 크기에 맞게 늘이고 줄이는 일을 이 도구가 대신해 줍니다.
새 게임을 시작할 때 복사하는 틀(`apps/_template`)에 이 도구가 이미 연결되어 있습니다.

미니게임 폴더에는 우리가 아가라고요용으로 만든 짐 정리, 파일 정리 10과 함께, 자리를 채우려고 넣어 둔 기존 게임 다섯 개와 추억의 플래시 게임 여덟 개, 추억의 영상 하나가 있습니다.
방에 놓은 게임기를 두 번 눌러도 같은 게임이 게임기 화면에 늘어섭니다(`src/apps/console-app.js`). 다른 사이트의 게임은 원래 창 크기로 띄운 뒤 게임기 화면에 맞게 줄여서 보여 줍니다.
파일 정리 10에는 100초 동안 많이 지우는 "보통" 모드와, 시간 제한 없이 끝까지 다 지울 수 있는 판을 주는 "시간 제한 없음" 모드가 있습니다(코드에서는 `casual`).
기존 게임들은 다른 주소에 있는 사이트라서, 그 게임을 따로 열었을 때의 이어 하기 기록과 아가라고요 안에서의 기록이 서로 따로 저장됩니다.
게임 창이 엉뚱한 페이지로 넘어가 버리면 창 안에 "다시 열기" 안내가 뜨고, 누르면 그 게임을 처음부터 다시 불러옵니다.

추억의 플래시 게임은 남의 게임이라 파일을 레포에 두지 않고 원작 주소로 이어 줍니다. 원작 페이지는 다른 사이트의 창 안에서 게임이 시작되지 않아서
새 탭으로 엽니다. 이런 아이콘은 오른쪽 아래에 화살표가 붙어 있고, 두 번 누르면 게임이 어느 사이트의 새 탭에서 열리는지 알려 주는 작은 창이 뜹니다.
"새 탭에서 열기"를 누르면 게임이 열립니다. 크라라 공주와 이상한 방처럼 난이도마다 주소가 다른 게임은 그 창에 "초급으로 열기", "중급으로 열기", "고급으로 열기"가 나오고,
아바타 스타 슈 영상은 "1화 보기"와 "전체 목록 보기" 가운데 고릅니다(`data/apps.js`의 `links`).

## 마우스 커서

모니터 화면 안에서는 마우스 커서도 그 시절 모양으로 바뀝니다. 평소에는 화살표, 누를 수 있는 곳에서는 손가락,
옮길 수 있는 가구 위에서는 편 손, 끄는 동안에는 쥔 손, 부팅 중에는 모래시계가 됩니다. 모니터 바깥에서는 원래 커서로 돌아옵니다.
커서 그림은 `src/cursors.js`가 만들어 화면 전체와 열려 있는 게임 창에 함께 씁니다. 마우스 앱에서 커서 색과 크기를 고르고 직접 그리던 기능은
알파 테스트 피드백을 보고 2026년 11월 10일에 뺐습니다.

## 화면 효과

모니터에는 브라운관 느낌을 내는 효과 두 가지가 늘 겹쳐 있습니다. 아주 약한 깜빡임과, 가운데보다 조금 어두운 화면 구석입니다.
둘 다 글자가 많은 화면 가운데는 거의 건드리지 않습니다.

모니터 아래 소리 단추를 누르면 그 시절 모니터가 화면 위에 띄우던 OSD 상자처럼 "소리 켜짐"이나 "소리 꺼짐"이 1.8초 동안 뜹니다(`src/main.js`의 `showOSD`).
전원을 켜기 전의 꺼진 화면에는 "신호 없음" 상자가 떠 있습니다. 델과 삼성 모니터가 신호가 없을 때 그랬듯이,
상자는 화면 가운데에서 출발해 끊김 없이 떠다니다가, 상자 가장자리가 화면 끝에 닿으면 방향을 바꿉니다(1초에 55px쯤).
전원을 켜면 그 시절 모니터처럼 자기 제거(디가우스)를 합니다. 화면이 1.2초에 걸쳐 데워지듯 밝아지고, 그동안 부팅 로고처럼 밝은 곳에만
색이 번졌다가 2초에 걸쳐 가라앉으며, 화면 떨림도 1.5초에 걸쳐 잦아듭니다. 소니 브라운관 모니터 설명서에는 켤 때의 자동 디가우스가 2~5초로 적혀 있습니다.
끌 때는 그림이 0.35초 만에 어두워집니다. 그 시절 모니터에는 끌 때 화면 한가운데에 밝은 점이 남지 않게 막는 보호 회로가 있어서,
옛 TV처럼 그림이 가로줄로 줄어들다 점으로 사라지지 않고 곧바로 꺼졌습니다.

예전에는 모니터 아래 "그레인"과 "볼록" 버튼으로 효과를 끄고 켰고, 1998 모습에서는 화면을 실제로 볼록하게 휘게 그린 뒤
그 위에 투명한 층을 덮어 누른 자리를 휘기 전 자리로 되돌려 전해 주었습니다. 2005로 정하면서 볼록 효과와 두 버튼을 뺐습니다.
가는 가로줄(스캔라인)은 글자의 가로획을 가려 읽기 어려워서 같은 날 뺐고(known-issues 55), 지직거리는 그레인은 2005년 PC 모니터에 없던 것이라 2026-11-11에 뺐습니다.
그래서 지금은 어느 브라우저에서나 화면이 평평하고, 누른 자리가 어긋나지 않으며, 창 안의 게임에도 마우스 입력이 그대로 들어갑니다.

## 화면 보호기

바탕화면을 2분 동안 그냥 두면 화면 보호기가 돕니다(`src/screensaver.js`). 2005년 무렵의 "스크롤 문자" 화면 보호기처럼
검은 화면 위로 주인의 인사말이 오른쪽에서 왼쪽으로 흘러가고, 지나갈 때마다 높이와 색이 바뀝니다.
마우스를 움직이거나 누르거나 키를 누르면 걷히고, 걷는 데 쓴 누르기는 화면 안으로 전하지 않아 가구나 아이콘이 눌리지 않습니다.
인사말은 공유하기 창에서 30자까지 적고, "미리 보기"로 바로 볼 수 있습니다. 인사말은 공유 링크에 같이 담겨 친구 화면에서도 흘러가고,
적지 않았으면 "주인 이름의 컴퓨터"가 흘러갑니다. 앞에 고른 창이 있거나(음악, 영상, 게임을 쓰는 중) 가구를 가까이 보는 중, 튜토리얼 중에는 돌지 않습니다.
기다리는 시간은 `src/config.js`의 `SAVER_MS`입니다.

## 소리

전원 버튼을 누르는 순간부터 소리가 납니다. 모니터 아래 "소리" 버튼에 불이 켜져 있으면 소리가 나고, 누르면 꺼집니다.
이 버튼은 전원을 켜기 전에도 보이므로 소리가 날지 미리 알 수 있고, 시작 메뉴의 "소리 끄기"도 같은 설정을 바꿉니다.
브라우저는 사용자가 한 번 누르기 전에는 소리를 막는데, 이 사이트는 전원 버튼을 눌러야 켜지므로 첫 소리도 그 뒤에 납니다.

효과음은 전원 버튼, 로그인 화면에서 아이디를 칠 때(한 글자마다), 켜진 화면 안을 누를 때(마우스), 아바타가 걸을 때(두 칸마다 발소리),
불을 끄고 켤 때, 방과 놀이터 사이를 오갈 때, 방 꾸미기에서 가구를 놓을 때 납니다. 키보드, 발소리, 가구 소리는 세 가지 가운데 하나가 무작위로 납니다.

배경음악은 바탕화면에서만 틀고, 내 방과 놀이터가 각각 다른 곡을 씁니다. 방 꾸미기 창(내 집을 꾸밀 때)과 짐 정리, 파일 정리 10 창이 열려 있으면 그 창의 곡으로 바뀌고,
여러 창이 열려 있으면 나중에 연 창의 곡이 나옵니다. 게임 안에 음악이 들어 있는 게임(앱 목록에서 `music: 'own'`)을 여는 동안에는 두 음악이 겹치지 않게 사이트 음악을 멈춥니다.
곡이 바뀔 때는 앞 곡을 줄이면서 다음 곡을 키우고, 멈춘 곡은 다음에 멈춘 자리부터 다시 나옵니다.
내 방 배경음악은 "배경음악" 앱에서 네 곡 가운데 고릅니다. 이 앱이 열려 있는 동안은 놀이터에 있어도 고른 곡이 나와 바로 들어 볼 수 있고,
"배경음악 틀기"를 끄면 효과음은 그대로 두고 배경음악만 멈춥니다.

미니게임처럼 창 안에서 도는 앱을 누를 때는 그 클릭이 바깥 문서까지 오지 않아서 마우스 소리가 나지 않습니다.
파일 이름과 곡마다 맞춘 크기는 `src/sound.js` 맨 위에, 원본의 어디를 잘라 썼는지는 `docs/requirements.md`의 "소리"에 있습니다.

## 이렇게 만든 이유

npm이나 빌드 도구를 쓰지 않고 HTML, CSS, 자바스크립트 파일만으로 만들었습니다. 따로 설치할 것 없이 파일을 받아 바로 열 수 있고,
GitHub Pages에 그대로 올리면 사이트가 되기 때문입니다. 팀원 누구나 같은 방법으로 열어 보고 고친다는 점을 가장 중요하게 봤습니다.

지금은 마우스를 쓰는 PC 화면을 기준으로 만듭니다. 옛 컴퓨터를 흉내 내는 사이트라 마우스로 누르고 끄는 경험이 중심이고,
휴대폰까지 함께 맞추면 할 일이 크게 늘어나기 때문입니다. 세로로 든 휴대폰에서는 모니터를 옆으로 돌려 보여 주는 정도만 남아 있습니다.

레포는 누구나 볼 수 있는 공개 레포입니다. 작업은 브랜치에서 하고 Pull Request로 올리며, PR을 열면 자동 점검이 먼저 돌아
목록의 오타나 그림 파일 이름 같은 흔한 실수를 잡아 줍니다. 검토와 합치기는 레포 관리자가 맡고, 합쳐지면 1~2분 뒤 사이트에 반영됩니다.
작업을 하나 마칠 때마다 `worklog/`에 일지를 남깁니다. 나중에 누가 그 코드를 고치더라도 왜 그렇게 만들었는지 찾아보게 하려는 것입니다.

## 아직 정하지 않은 것

팀에서 정해야 하는 것과 이미 정한 것은 `docs/requirements.md`의 "아직 정하지 않은 것"과 "정한 것"에 한데 모아 두었습니다.
정해지면 그 문서를 먼저 고치고, 사이트가 바뀌면 이 설명서의 해당 절도 함께 고칩니다.

## 낱말 풀이

| 낱말 | 뜻 |
| --- | --- |
| 기믹 | 바탕화면에서 가구를 두 번 눌렀을 때 아바타가 다가가 일으키는 일. 밤 바꾸기, 앱 열기 |
| 쪽지 | 손님이 코르크 보드에 붙이는 포스트잇 한 장(방명록 글 하나). 서버에 있다 |
| 공간 | 내 방, 놀이터처럼 가구를 놓는 장소. 바탕화면에서는 현관문, 놀이터 아이콘, 놀이터의 아파트 문으로 오가고, 방 꾸미기에서는 위쪽 탭으로 고른다 |
| 이웃집 | 팀원이 꾸민 방의 공유 링크를 `data/neighbors.js`에 넣은 집. 로그인 화면과 놀이터 울타리의 문패로 놀러 간다 |
| 아이소메트릭 | 방을 비스듬히 위에서 내려다보는 그림 방식 |
| 앱 | 아가라고요 창 안에 뜨는 프로그램. 방 꾸미기처럼 OS가 직접 그리는 기본 앱과, 팀원이 만드는 웹페이지 앱이 있다 |
| iframe | 웹페이지 안에 다른 웹페이지를 끼워 보여 주는 HTML 기능. 팀원 앱이 창 안에 뜨는 방식 |
| SDK | 팀원 앱이 아가라고요와 주고받을 때 쓰는 작은 도구(`apps/aga-sdk.js`) |
| localStorage | 브라우저가 사이트마다 따로 마련해 두는 저장 공간. 내 방과 게임 기록이 여기에 저장된다 |
| 클릭 지점 | 커서 그림에서 실제로 눌리는 한 칸. 예전 커서 편집기에서는 핫스팟이라고 불렀다 |
| PR(Pull Request) | 내 브랜치의 작업을 main에 합쳐 달라는 요청. GitHub에서 열고 검토한다 |
| 자동 점검 | PR을 열면 GitHub이 `tools/check.py`로 흔한 실수를 찾아 주는 과정 |
