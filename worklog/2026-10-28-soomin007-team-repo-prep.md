캐시 지문(stamp.py)은 사람이 돌리지 않고 배포할 때 GitHub Actions가 돌리게 바꿨다. 이 레포를 그대로 팀 조직의 새 레포로 복사할 예정이다.

## 정한 것과 이유
- 지금 레포를 이전(Transfer)하지 않고 새 레포에 복사한다. 이미 공유한 데모 주소가 깨지지 않게 하려는 것이다.
- 팀원은 브랜치에서 작업하고 PR을 열며, 레포 관리자가 합친다. main이 곧 배포본이라 실수가 바로 사이트에 나가지 않게 한다.
- 지문 찍기를 배포 단계로 옮겼다. 사람마다 찍으면 index.html이 PR마다 충돌하고, 한 명만 잊어도 배포 직후 옛 화면이 나온다.
  레포의 파일은 여전히 빌드 없이 그대로 열린다.
- 일지는 날짜별 한 파일이 아니라 작업 한 덩어리(대개 PR 하나)마다 한 파일이다. 여러 사람이 같은 날짜 파일을 고치면 충돌하기 때문이다.
  파일 이름은 영어 소문자로 짓는다(한글 파일 이름은 맥과 윈도우에서 다르게 저장된다).
- AI 규칙은 여러 도구가 함께 읽는 `AGENTS.md`에 두고, `CLAUDE.md`는 그 파일을 불러오기만 한다.

- 팀원 초대와 레포 쓰기 권한은 팀원 GitHub 아이디를 받은 뒤에 한다.

## 이어서: 파일만 올리는 방법과 Issues 양식

README의 "작업을 올리는 방법"을 무엇을 올리느냐에 따라 셋으로 나눴다. 코드는 지금처럼 브랜치와 PR로 올리고,
그림이나 소리 파일은 웹의 Upload files로 올리며(main 보호 때문에 GitHub이 브랜치와 PR을 알아서 만든다), 의견은 Issues에 남긴다.
Issues에는 버그 제보(`.github/ISSUE_TEMPLATE/bug.yml`)와 아이디어(`idea.yml`) 양식을 두고, `idea` 라벨을 만들었다.
역할별 안내를 따로 쓰지 않은 것은, 역할이 달라도 올리는 방식은 이 셋뿐이기 때문이다.
버그 양식에는 시대, 컴퓨터와 브라우저, 재현 여부를 묻는 칸을 넣었다. 특정 환경에서만 생기는 버그가 실제로 있었다.

## 이어서: 승인 1개가 있어야 합쳐지게

main 보호를 "PR 필수, 승인 0명"에서 "승인 1명, 새 커밋이 오면 승인 해제"로 바꿨다. 승인 0명이면 쓰기 권한이 있는 사람이 자기 PR을 스스로 합칠 수 있어서,
문서에 적은 "관리자가 합친다"가 실제로는 막혀 있지 않았다. 검토와 합치기는 김수민(Admin)과 전유빈(Maintain)이 맡고, README와 AGENTS.md에 적었다.
Admin은 보호 규칙을 건너뛸 수 있어서 레포 관리자 자신의 PR은 승인 없이 합칠 수 있다.

## 이어서: AI 규칙을 처음 세팅한 사람 기준으로

AGENTS.md와 CLAUDE.md를 개인 설정이 하나도 없는 사람의 AI가 읽는다고 보고 다시 썼다. 사람 이름, 특정인의 브랜치 예시,
개인 전역 설정(세션 로그 루틴)을 가리키는 문장을 빼고, 개조식으로 바꿨다.
처음 쓰는 AI가 자주 하는 실수(npm 설치, `python -m http.server`, 강제 push, 커밋 전 확인 없이 PR 열기)를 막는 줄을 더했다.
한 사람의 PC에만 필요한 메모는 `CLAUDE.local.md`(.gitignore)로 옮기는 자리를 만들었다.

## 이어서: 승인 개수를 다시 0으로

승인 1명 규칙을 다시 0명으로 돌렸다. 작업 대부분을 레포 관리자가 하는데, 자기 PR은 스스로 승인할 수 없어 매번 관리자 우회로 합쳐야 했다.
팀원들은 주로 파일 올리기와 Issues를 쓸 예정이라 혼자 합칠 위험이 작다. PR 필수, 강제 push와 main 삭제 금지는 그대로 두었고,
"Write 권한자는 자기 PR을 합치지 않는다"는 약속을 README와 AGENTS.md에 적었다. 코드를 올리는 팀원이 늘면 다시 1명으로 올린다.
