# 2026-10-28 팀 레포로 옮길 준비 (soomin007)

## 한 일
여러 사람이 같이 작업할 수 있도록 레포 첫 화면 안내, AI 도구용 규칙, PR 양식, 작업 일지 형식을 만들었다.
캐시 지문(stamp.py)은 사람이 돌리지 않고 배포할 때 GitHub Actions가 돌리게 바꿨다. 이 레포를 그대로 팀 조직의 새 레포로 복사할 예정이다.

## 바꾼 파일
- `README.md`(새 파일): 프로젝트 소개, 로컬 실행, 브랜치와 PR로 올리는 순서, 어디를 고치면 되는지, 기록 남기기
- `AGENTS.md`(새 파일): AI 도구가 읽는 팀 공통 규칙. 예전 `CLAUDE.md`의 구조와 규칙을 옮기고 팀 작업 방식을 더했다
- `CLAUDE.md`: `@AGENTS.md`를 불러오고 Claude Code 전용 내용만 남겼다
- `.github/workflows/pages.yml`(새 파일): main에 합쳐지면 stamp.py를 돌리고 Pages로 배포
- `.github/pull_request_template.md`(새 파일): PR 설명 칸의 질문과 확인 항목
- `worklog/README.md`(새 파일): 일지 형식. 예전 `session_logs/` 두 편을 `worklog/`로 옮겼다
- `known-issues.md`: 15번(지문은 Actions가 찍는다), 17번(팀 레포에서는 기존 게임들이 다른 사이트가 된다)
- `tools/stamp.py`: 머리 주석

## 정한 것과 이유
- 지금 레포를 이전(Transfer)하지 않고 새 레포에 복사한다. 이미 공유한 데모 주소가 깨지지 않게 하려는 것이다.
- 팀원은 브랜치에서 작업하고 PR을 열며, 레포 관리자가 합친다. main이 곧 배포본이라 실수가 바로 사이트에 나가지 않게 한다.
- 지문 찍기를 배포 단계로 옮겼다. 사람마다 찍으면 index.html이 PR마다 충돌하고, 한 명만 잊어도 배포 직후 옛 화면이 나온다.
  레포의 파일은 여전히 빌드 없이 그대로 열린다.
- 일지는 날짜별 한 파일이 아니라 작업 한 덩어리(대개 PR 하나)마다 한 파일이다. 여러 사람이 같은 날짜 파일을 고치면 충돌하기 때문이다.
  파일 이름은 영어 소문자로 짓는다(한글 파일 이름은 맥과 윈도우에서 다르게 저장된다).
- AI 규칙은 여러 도구가 함께 읽는 `AGENTS.md`에 두고, `CLAUDE.md`는 그 파일을 불러오기만 한다.

## 남은 일과 알아 둘 것
- 조직(Organization)을 만들고 새 레포로 복사한 뒤, Pages Source를 "GitHub Actions"로 바꾸고 main 브랜치 보호를 켠다.
- 새 레포 주소가 정해지면 README 맨 위 배포 주소를 바꾼다.
- 기존 게임들은 팀 레포에서 다른 사이트가 되어, 혼자 열 때의 이어 하기 기록과 따로 저장된다(known-issues 17).
- 이 데모 레포는 아직 Pages가 예전 방식(브랜치 배포)이라, 워크플로가 올라가면 배포 단계가 실패한다. 이쪽도 Actions로 바꾸거나 워크플로를 빼야 한다.
