# 2026-11-01 화면 안 커서 (soomin007)

## 한 일
모니터 화면 안에서만 커서를 우리가 그린 모양으로 바꿨다. 시대마다 화살표와 기다림 모양이 다르고, 누를 수 있는 곳은 손가락,
가구를 잡을 수 있는 곳은 편 손, 끄는 중에는 쥔 손, 부팅 중에는 모래시계(2010은 파란 고리)가 된다. 모니터 바깥은 브라우저 기본 커서 그대로다.

## 바꾼 파일
- `style.css`: `body`에 `--cur-arrow`, `--cur-hand`, `--cur-grab`, `--cur-grabbing`, `--cur-wait`(SVG data URI), 2005와 2010 덮어쓰기.
  화면 안 요소의 `pointer`, `grab`, `move`, `default`를 이 변수로 바꿨다(18곳). 시대 스위치와 모니터 버튼은 그대로
- `src/os.js`: 앱이 `cursor`를 요청하면 커서 묶음을 보내고, 시대가 바뀌면 열린 앱에 다시 보낸다
- `apps/aga-sdk.js`: 받은 커서를 `--aga-*` 변수로 넣고, 기본 커서를 시대 화살표로(`:where(html)`, 앱 규칙이 항상 이긴다)
- `apps/tidy-up`, `apps/file-ten`: 버튼에 `cursor: var(--aga-hand, pointer)`
- `apps/README.md`: 앱에서 커서 변수를 쓰는 법

## 정한 것과 이유
- 화면 속에 커서를 직접 그리는 방법 대신 CSS 커서를 썼다. 반응이 늦지 않고, 다른 사이트 게임 창 위에서 커서가 멈추는 문제가 없다.
- 그림은 실제 운영체제 커서를 가져오지 않고 직접 그렸다. 32px, 핫스팟은 화살표 끝(2,2), 손가락 끝(13,3).
- 1998 볼록 화면은 `crt.js`가 아래 요소의 커서를 입력층에 옮겨 주던 코드가 이미 있어서 그대로 동작한다.
- 다른 사이트 게임(기존 게임들)은 SDK가 없어서 그 게임의 커서가 나온다. 게임 화면에서는 그쪽이 자연스럽다고 보았다.

## 남은 일과 알아 둘 것
- 확인: 로컬 서버에서 15개 커서 그림이 모두 32px로 읽히는지, 화면 안 요소와 짐 정리 창 안의 계산된 커서, 1998 입력층의 손가락,
  시대를 바꿀 때 열린 앱의 커서가 바뀌는지를 봤다. 실제 마우스로 움직여 본 모습은 사람 눈으로 한 번 더 보면 좋다.
- SVG 커서를 지원하지 않는 브라우저에서는 뒤에 적은 기본 커서(default, pointer 등)가 나온다.
