# 2026-11-02 사람용 설명서와 파일 지도 (soomin007)

## 한 일
AI 도구용 규칙(AGENTS.md)과 따로, 사람이 읽는 설명서(`docs/guide.md`)와 파일 지도(`docs/file-map.md`)를 만들었다.
설명서는 코드를 읽지 않고도 사이트가 어떻게 동작하고 왜 이렇게 만들었는지 알 수 있게 쓴 글이고,
파일 지도는 어떤 파일이 어디에 있고 무엇을 하는지, 무엇을 고치려면 어디로 가야 하는지를 표로 모은 것이다.

## 바꾼 파일
- `docs/guide.md`(새 파일): 옛 컴퓨터 한 대, 세 시대, 방 꾸미기, 가구 기믹, 저장과 공유, 앱과 미니게임, 마우스와 커서, 화면 효과, 만든 이유, 정하지 않은 것, 낱말 풀이
- `docs/file-map.md`(새 파일): 자주 찾는 것, 폴더별 파일 표(하는 일, 내보내는 것), 누가 누구를 부르나, style.css 안의 순서
- `tools/check.py`: 파일 지도 점검. src, data, tools, docs, .github의 파일과 맨 위 핵심 파일이 지도에 빠졌거나, 지도에 적힌 경로가 없으면 오류
- `AGENTS.md`: 작업 시작 전에 파일 지도부터 보기, 파일을 옮기면 지도도 고치기. 구조 절은 지도로 넘기고 큰 그림만 남겼다
- `README.md`: 설명서와 파일 지도 링크
- `style.css`: 그레인 절에 남아 있던 옛 설명(캔버스를 매 프레임 칠한다)을 지웠다

## 정한 것과 이유
- 사람용 설명서는 사용법(README)이나 규칙(AGENTS.md)과 겹치지 않게, 동작과 이유만 문단으로 썼다. 쓰기 전에 기획 문서의 문체와 한국어 AI 문체 점검 목록(쉼표 과다, 번역투, 가능 표현 남발 등)을 확인했다.
- 파일 목록은 한곳(파일 지도)에만 두고 AGENTS.md는 그쪽을 가리키게 했다. 두 곳에 두면 한쪽이 낡는다.
- 지도가 낡지 않게 자동 점검에 넣었다. 일부러 파일을 하나 더하고, 지도의 경로를 하나 틀리게 해서 둘 다 잡히는 것을 확인했다.
- 설명서 내용은 코드와 대조했다. 그 과정에서 "그레인 버튼이 가장자리 어두움까지 끈다"는 처음 문장이 틀린 것을 찾아 고쳤다(가장자리는 볼록 버튼).

## 남은 일과 알아 둘 것
- 사이트 동작이 바뀌면 설명서의 해당 절도 같이 고친다. 설명서는 자동 점검이 보지 않는다.
