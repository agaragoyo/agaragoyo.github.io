# 2026-11-04 튜토리얼 다시 보기를 빈 연습 방으로 (soomin007)

## 한 일
시작 메뉴의 "튜토리얼 다시 보기"를 눌러도 이미 침대, 스탠드, 창문을 놓은 사람은 놓는 단계가 저절로 지나가서, 처음부터 보려면 계정을 지워야 했다.
튜토리얼을 다시 시험해 보려면 계정을 지우지 않고 첫 단계부터 볼 수 있어야 해서, 다시 보기를 저장된 방을 건드리지 않는 빈 연습 방에서 진행하게 바꿨다.

## 바꾼 파일
- `src/tutorial.js`: 시작 전 안내 창, 연습 시작과 끝, 연습 중에는 진행 상태를 저장하지 않기, 연습에 맞는 단추와 문구
- `src/os.js`: 연습 방 바꿔 끼우기(`os.realHome`, `os.startPractice`, `os.endPractice`), 연습 중 저장 막기, 연습 중 시작 메뉴에서 다시 보기 빼기
- `src/settings.js`: 저장하지 않고 잠시 다른 값으로 쓰는 `hold`, `release`
- `src/apps/share-app.js`: 연습 중에는 저장된 내 방의 링크와 PNG를 내보내고, 그 사실을 창에 적기
- `known-issues.md`: 40번
- `docs/guide.md`, `docs/requirements.md`, `docs/file-map.md`, `docs/tasks.md`, `docs/checklists.md`: 다시 보기 설명

## 정한 것과 이유
- PR 39에서는 연습용 빈 방이 공유 링크, 저장, 창 다시 그리기까지 갈래를 늘린다고 보고 버렸다. 그 판단을 뒤집은 것은 다시 보기로 첫 단계를 볼 수 없으면 기능이 제 몫을 못 하기 때문이다.
  코드를 다시 읽어 보니 화면과 창이 모두 `os.home`을 읽어서 바꿔 끼우기 한 번이면 되고, 막을 곳은 저장과 공유, 밤낮 셋뿐이었다.
- 연습 방과 밤낮 값은 메모리에만 둔다. 새로 고침을 하면 저절로 사라지므로 되돌리는 코드가 필요 없고, 도중에 무슨 일이 생겨도 저장된 값이 바뀔 길이 없다.
- 밤낮은 값을 저장했다가 돌려놓지 않고 `settings.hold`로 잡아 둔다. 돌려놓는 방식은 연습 중에 새로 고침을 하면 연습의 밤이 저장된 채로 남는다.
- 연습은 언제나 낮에서 시작한다. 밤을 켜 둔 사람도 처음처럼 스탠드로 밤을 켰다가 끄는 순서를 볼 수 있고, 끝나면 원래 밤 설정으로 돌아온다.
- 공유하기는 숨기지 않고 저장된 내 방을 내보낸다. 숨기면 방 꾸미기의 공유 링크 단추까지 따로 막아야 하고, 어느 쪽이든 연습 방은 밖으로 나가지 않는다. 창에 연습 방은 공유되지 않는다고 적었다.
- 연습을 시작하고 끝낼 때 바탕화면을 `showDesktop`으로 새로 만든다. 그래야 가구로 걸어가던 아바타의 예약이 사라지고, 연습이 끝난 뒤에 스탠드 기믹이 진짜 밤낮을 바꾸지 않는다.
- 연습을 시작할 때는 첫 단계가 가려지지 않게 창을 모두 닫고, 끝날 때는 연습 방을 보여 주던 방 꾸미기와 공유하기 창만 닫는다. 연습 중에 연 게임까지 말없이 닫으면 안 되기 때문이다.
- 카드의 단추는 연습 중에 "내 방으로 돌아가기" 하나로 둔다. 눌렀을 때의 결과를 말하고, 지금 있는 곳이 연습 방이라는 것도 함께 알려 준다(known-issues 32).
- 안내 창은 "지금 방은 그대로 두고 빈 방에서 연습합니다"를 첫 줄에 쓰고, 단추는 "빈 방에서 연습하기"와 "취소"로 뒀다. 창이 닫힌다는 말은 열린 창이 있을 때만 적는다.
- 처음 튜토리얼을 하던 사람이 다시 보기를 누르면 연습이 끝난 뒤 하던 자리로 돌아온다. 연습 중에는 진행 상태를 저장하지 않아서 저장소의 값을 다시 읽기만 하면 된다.
- 놓은 가구는 바로 저장된다는 안내는 연습 방에서 거짓이 되므로 "평소에는"을 붙였다. 끝 카드의 시작 메뉴 안내는 방금 그 메뉴를 쓴 사람에게 필요 없어서 연습에서는 뺐다.

## 남은 일과 알아 둘 것
- 집을 저장하거나 밖으로 내보내는 코드를 새로 쓰면 `os.home` 대신 `os.realHome || os.home`을 읽어야 한다(known-issues 40).
- 연습 중 새로 고침을 하면 연습은 이어지지 않고 끝난다. 임시 방을 저장하지 않으려고 고른 동작이다.
- 확인은 화면 없는 크롬에 진짜 마우스 입력을 넣는 점검 스크립트로 했다. 가구를 놓아 둔 시험 사용자로 처음부터 끝까지, 도중의 돌아가기, 새로 고침, 로그아웃, 전원 끄기, 밤을 켜 둔 사용자, 걷는 중에 끝내기, 첫 튜토리얼 중의 다시 보기를 돌렸고, 1998과 2005, 2010에서 시대마다 133개가 넘는 항목이 통과했다.
  처음 온 사람의 흐름도 1998과 2010에서 52개 항목이 그대로 통과했다. 1998은 볼록 화면의 보정 층을 거치는 실제 좌표로 눌렀다. 스크립트는 레포에 넣지 않았다.
- 같은 방의 PNG도 드물게 파일 해시가 달라질 수 있다. 스크린샷을 찍어 가며 시험할 때 벽 가구 모서리의 픽셀 하나가 색 값 1만큼 달라진 적이 있었고, 눈으로는 구분할 수 없는 그리기 오차였다. 같은 방인지 볼 때는 해시보다 공유 링크와 픽셀 차이를 본다.
- 사파리와 파이어폭스에서는 돌려 보지 못했다.
