# 2026-11-11 짧은 공유 링크와 Firebase (soomin007)

## 한 일
가구에 글을 많이 담은 방은 짧은 형식(`#r=`)으로 만들어도 공유 링크가 1,230자라 카카오톡에서 잘렸다.
방을 서버(Firebase의 Firestore)에 두고 링크에는 번호만 담는 짧은 링크(`#s=`, 39자)를 시험으로 넣었다(요구 사항 F21).
공유하기 창에서 "짧은 링크 만들기"를 누르면 방을 올리고, 그 뒤에는 방을 고칠 때마다 3초 뒤에 서버의 방도 따라 고친다.
짧은 링크로 온 손님의 브라우저는 부팅하는 동안 서버에서 방을 받아 온다. 서버를 고르기 전에 방명록까지 놓고 Supabase와 다시 비교했다.

## 바꾼 파일
- `src/cloud.js`(새 파일): Firestore와 익명 로그인의 REST 주소를 fetch로 부르는 서버 모듈. 방 받기(`fetchHome`), 만들기(`share`), 지우기(`unshare`),
  고친 방 따라 올리기(`syncLater`, `syncNow`). 탭을 닫을 때 기다리던 것은 keepalive로 바로 올리고, 못 올렸으면 다음에 내 컴퓨터로 들어올 때 올린다
- `firestore.rules`(새 파일): 서버의 보안 규칙. Firebase 콘솔에 게시한 것과 같다
- `src/share.js`: 짧은 링크의 번호를 읽는 `linkId`
- `src/os.js`: 짧은 링크의 방을 부팅 중에 받고, 로그인 화면에 "친구 방, 불러오는 중" 자리를 두었다가 받으면 "손님으로 구경하기"로 바꾼다.
  없는 방과 서버에 닿지 못한 경우는 알림으로 알린다. 저장할 때 서버의 방도 따라 고치고, 초기화는 서버의 방도 지운다
- `src/apps/share-app.js`: 짧은 링크 만들기, 긴 링크 복사, 짧은 링크 지우기(무엇이 일어나는지 보여 준 뒤 "지우기"와 "그대로 두기"로 받는다).
  긴 링크가 500자를 넘으면 글자 수와 카카오톡에서 잘린다는 것을 알린다. 창 높이를 420에서 440으로 늘려 본문 스크롤을 없앴다
- `src/config.js`: 저장 키 `agarago.cloud`
- `tools/check.py`: 구글 API 키는 `src/cloud.js`에만 있게 하고(`check_secrets`), 규칙 파일이 있는지와 방 글자 수 한도, 컬렉션 이름이 코드와 같은지 본다(`check_cloud`).
  파일 지도가 `firestore.rules`도 적었는지 본다
- `assets/fonts/aga-ui.woff2`, `aga-ui-bold.woff2`, `aga-ui.txt`: 새 문구의 글자를 넣어 첫 화면 작은 글꼴을 다시 만들었다(494자)
- 문서: `AGENTS.md`(API 키 예외, 서버에 붙이는 곳, 구조), `docs/guide.md`(저장과 공유), `docs/requirements.md`(F21, 지켜야 할 것, 아직 정하지 않은 것, 정한 것),
  `docs/tasks.md`, `docs/checklists.md`, `docs/file-map.md`, `known-issues.md`(59)

## 정한 것과 이유
- 서버는 Firebase로 정했다. Supabase 무료 플랜은 7일 동안 활동이 적으면 프로젝트를 멈추고, 흔히 깨우는 데 쓰는 GitHub Actions 예약 실행은
  공개 레포에서 60일 동안 활동이 없으면 꺼진다. 학기가 끝나 커밋이 멈추면 몇 달 뒤 보낸 링크가 끊긴다. Firebase 무료 플랜은 멈추지 않는다.
  방명록에 필요한 것(손님 누구나 쓰기, 글자 수 제한, 고치기 금지, 방 주인만 지우기)은 Firestore 규칙으로 서버 코드 없이 된다.
  Supabase가 앞서는 SQL 순위와 검색, 넉넉한 읽기 횟수는 요구 사항에 없다.
- SDK 대신 REST를 fetch로 부른다. SDK는 첫 화면을 무겁게 하고 저장소에 `agarago.`로 시작하지 않는 키를 쓴다. 손님은 로그인 없이 GET 한 번이면 된다.
- 쓰기는 익명 로그인으로 한다. 규칙은 문서의 uid가 로그인한 사용자와 같을 때만 고치고 지우게 한다. 목록 읽기를 막아 남의 방 번호를 모을 수 없게 했다.
- 방 문서에는 uid, code(긴 링크의 `#r=` 뒤와 같은 글자), updatedAt(서버 시각) 세 칸만 둔다. 같은 글자라서 읽을 때 `decodeHome` 검사를 그대로 거친다.
  글자 수 한도 30,000자는 가구 내용을 모두 꽉 채운 방(1만 7천 자쯤)의 두 배쯤으로 잡았다.
- 처음 올리기는 주인이 단추로 고른다. 방이 서버에 저장된다는 것을 누르기 전에 보여 주려는 것이고, 링크만 보려고 창을 연 사람까지 익명 계정을 만들지 않으려는 것이다
  (익명 계정은 인터넷 주소 하나에서 한 시간에 100개까지 만들어진다).
- 긴 링크는 그대로 둔다. 서버가 막히거나 하루 한도를 넘긴 날, 발표 날 한 와이파이에서 계정 만들기가 막힌 경우에 쓴다. 이웃집 목록도 긴 링크로 둔다.
- 짧은 링크 지우기와 이 컴퓨터 초기화는 서버의 방도 지운다. 서버에 올린 방은 주인이 지울 수 있어야 한다.
- API 키는 Firebase가 만들 때부터 Firebase API만 부를 수 있게 묶여 있었다(유튜브 API를 불러 `API_KEY_SERVICE_BLOCKED`로 확인했다).
  사이트 주소로까지 묶으면 다른 포트에서 도는 로컬 시험이 막혀서 지금은 묶지 않았다.

## 남은 일과 알아 둘 것
- 확인: `python tools/check.py` 오류 0개(경고 2개는 원래 있던 침대와 라디오 그림), `node tools/night-contrast.mjs` 실패 0개.
  콘솔에 게시한 규칙을 REST로 26가지 불러 보았다(만들기, 로그인 없이 읽기, 목록 막힘, 남의 방 고치기와 지우기 막힘, 다른 칸, 번호 꼴, 글자 수 한도, 시각 직접 적기 막힘, 토큰 갱신). 모두 맞았다.
  화면 없는 크롬으로 주인과 손님(저장소가 빈 다른 사용자)을 흉내 내 끝까지 50가지를 시험해 모두 통과했다. 만들기는 1.5초 걸렸고, 고친 방은 3초 뒤에 서버에 올라갔다.
  없는 방과 서버가 막힌 경우의 알림, 지우기, 초기화도 봤다. 시험에 쓴 문서와 익명 계정은 지웠다.
- 규칙을 고치면 PR을 합친 뒤 콘솔에도 게시한다(known-issues 59).
- 짧은 링크를 만든 브라우저의 저장소를 지우면 그 링크의 방은 더 고칠 수 없다. 익명 계정이 그 브라우저에만 있기 때문이다. 필요해지면 구글 로그인 연결을 붙인다.
- 방명록은 같은 서버의 `homes/{번호}/notes` 같은 하위 컬렉션으로 둘 수 있다. Firestore는 문서마다 읽기를 세므로 쪽지는 보드를 열 때만 받는다.
- 공유하기 창은 폭이 540으로 고정이고 무대가 통째로 줄어들어, 줄 끝은 화면 크기와 상관없이 같다. 창 글을 고치면 창을 찍어 줄 끝을 본다.
