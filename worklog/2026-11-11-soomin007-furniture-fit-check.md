# 2026-11-11 가구 그림이 칸에 맞는지 자동 점검 (soomin007)

## 한 일
가구 그림이 칸에 맞는지 보는 일을 사람 대신 기계가 하게 만들었다. `tools/check.py`에 `check_furniture_fit`을 더해, `assets/furniture/<id>.png`를 사이트가 그리는 것과 같은 식으로 상자에 얹어 재고 어긋나면 경고한다.
가구 그림을 곧 전부 새로 그리는데, 그림 담당이 GitHub 웹에서 PNG를 올려 PR을 만들면 `docs/checklists.md`의 항목은 눈으로만 볼 수 있어 바닥에서 튀어나온 그림이나 칸을 다 못 채운 그림을 놓치기 쉽다.
지금 그림 23장 가운데 침대(바닥 변보다 12px 튀어나옴, 가장 아래 점이 앞 꼭짓점보다 13px 왼쪽)와 라디오(칠해진 폭이 칸 폭의 64%, 가장 아래 점이 18px 왼쪽) 둘만 경고가 나오고 오류는 0개다.

## 바꾼 파일
- `tools/check.py`: PNG를 푸는 `png_alpha`, 열마다 가장 아래 칠해진 점을 찾는 `painted_bottoms`, 바닥과 책상 위 가구를 재는 `fit_floor`, 벽 가구를 재는 `fit_wall`, 이를 부르는 `check_furniture_fit`. 기준 값은 `FIT_*` 상수
- `docs/checklists.md`: 가구 그림 항목 아래에 자동 점검이 경고하는 것과 기준을 한 줄 더함
- `docs/file-map.md`, `docs/tasks.md`: `tools/check.py` 설명과 가구 그림 할 일에 새 점검을 적음

## 정한 것과 이유
- PNG는 `zlib`과 `struct`로 직접 푼다. 이 레포는 파이썬 표준 라이브러리만 쓰고 GitHub Actions에도 pillow가 없다. 8비트 비인터레이스의 RGBA, RGB, 팔레트(tRNS 투명도)를 읽고, 16비트, 인터레이스, 회색이거나 깨진 파일은 "칸에 맞는지 재지 못했다"고 경고한다.
  PNG 필터는 채널마다 따로 풀어도 같아서 RGBA는 알파 채널만 풀었다. 1000×800 그림을 Paeth 필터로만 채워 풀어도 0.2초라, `python tools/check.py` 전체 시간(3.7초)은 그대로다.
- 재는 식은 `src/iso.js`의 `boxSize`와 `style.css`의 `.furn img`(`object-fit: contain`, 아래 가운데)를 따른다. 알파 64 이상을 칠해진 점으로 보고, 열마다 가장 아래 칠해진 점을 모아 세 가지를 본다.
  바닥과 책상 위 가구는 바닥 변보다 6px를 넘게 아래로 나오는지, 칸 수의 합이 3 이상인 가구는 칠해진 폭이 상자 폭의 85% 이상이고 가장 아래 점이 앞 꼭짓점에서 10px 이내인지, 벽 가구는 아래 변의 기울기가 3도 이내인지다.
- 가장 아래 점의 x는 한 열이 아니라 가장 아래에서 1px 이내에 있는 열들의 평균으로 잰다. 바닥이 평평한 그림에서 가장 왼쪽 열이 어디냐에 따라 값이 흔들리는 것을 피하려는 것이다.
- 오류가 아니라 경고로 한다. 이미 올라간 그림이 있고 고치는 데 시간이 걸리기 때문이다. 그림이 없는 가구와 돌린 그림(`-r.png`)은 말없이 건너뛴다. 사이트의 상자 식이나 `.furn img` 규칙이 바뀌어 점검이 틀어지는 것은 오류로 알려서 점검 도구도 같이 고치게 한다.
- 경고 문구는 반올림하면 허용 한도 이하로 보이는 숫자(6.3px)를 소수 한 자리로 적는다. 6px 허용인데 "6px 튀어나온다"고 나오면 헷갈리기 때문이다.

## 확인한 것
- PNG 풀기는 합성 PNG 28개(RGBA 필터 0~4와 줄마다 섞기, IDAT 쪼개기, 팔레트와 tRNS, RGB)와 지금 그림 23장, 모두 126만 점을 윈도우 GDI+가 푼 알파와 한 점씩 견주어 다른 점이 없었다.
- 일부러 틀린 합성 그림으로 경고가 나는지 봤다. 칸에 꽉 찬 네모, 칸보다 작은 상자, 27도와 4도와 3.2도 기운 창문은 경고가 났고, 2도 기운 창문과 칸에 꼭 맞는 상자는 통과했다.
  16비트 PNG, 깨진 파일, 통째로 투명한 그림은 "재지 못했다" 계열의 경고가 났고 멈추지 않았다. 높이가 없는 가구와 모르는 zone은 건너뛰었다.
- `python tools/check.py`는 오류 0개, 경고 2개(침대, 라디오). `git diff --stat`과 `--ignore-cr-at-eol --stat`의 줄 수가 같다.

## 남은 일과 알아 둘 것
- 경고는 PR의 점검을 실패로 만들지 않아서 PR 화면에서는 눈에 띄지 않는다. 그림 담당이 GitHub 웹으로 올릴 때 보이게 하려면 점검이 Actions 안에서 `::warning file=...::` 주석을 내게 하는 방법이 있다. 이번에는 하지 않았다.
- 기준 값은 지금 그림 23장으로 정했다. 통과하는 그림의 최댓값은 튀어나옴 4.9px(책장, 냉장고), 가장 아래 점의 어긋남 4.8px(냉장고)다. 새로 그린 그림에서 부당한 경고가 나오면 `FIT_*` 상수를 조정한다.
- 1×1 같은 작은 가구는 튀어나옴만 본다. 일부러 작게 그린 물건(라디오)은 그림을 칸에 맞게 다시 그리거나, `data/furniture.js`의 `size`를 그림에 맞게 줄인다.
- 침대와 라디오의 경고는 그림 담당이 그림을 고쳐야 사라진다.
