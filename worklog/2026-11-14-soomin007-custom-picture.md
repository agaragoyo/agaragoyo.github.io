# 2026-11-14 그림 파일로 만드는 프로필 사진 (soomin007)

## 한 일
프로필 사진(F25)을 사용자가 고른 그림 파일로도 만들 수 있게 했습니다(F26, 시험).
새 사용자 만들기와 사진 바꾸기 창의 사진 줄 아래에 "그림 파일 찾아보기"를 두었고, 파일을 고르면 브라우저가 가운데를 정사각형으로 잘라
24×24칸, 16색 이하의 픽셀 그림으로 줄인 뒤 큰 사진 자리에 보여 줍니다. 원본 파일은 저장하지 않고 줄인 그림만 `agarago.picture`에 남깁니다.
줄인 그림은 짧은 링크의 방에만 담고, 긴 링크로 온 손님에게는 이름의 첫 글자가 보입니다.

## 바꾼 파일
- `src/custom-picture.js`: 새 파일. 그림 파일 줄이기(중앙값 자르기와 k-평균, 4096색), 내 그림 바이트 적기와 풀기, 사진 값('my:' 뒤에 base64url)
- `src/user-pictures.js`: 사진 값에 내 그림을 받고, 고르는 줄 아래에 그림 파일 찾아보기, 사진 바꾸기 창의 안내 한 줄, `withPicture(home, 'long')`
- `src/share.js`: 짧은 형식 5의 덧붙임 바이트에서 사진 번호 자리가 255면 [그림 바이트 수][그림 바이트]가 뒤따른다. 집 검사가 내 그림을 풀어 본다
- `src/apps/share-app.js`: 긴 링크는 내 그림을 빼고 만들고, 내 그림을 쓰는 주인에게 짧은 링크에만 담긴다고 알린다
- `src/login.js`, `src/os.js`, `style.css`: 새 사용자 칸에 넘기는 알림 함수, 주석, 그림 파일 찾아보기와 안내 줄의 모양(밤 짝 포함)
- `tools/link-fuzz.mjs`: 무작위 내 그림과 망가진 내 그림, 덧붙임 바이트 모양과 옛 페이지가 건너뛰는지 보는 시험
- `tools/smoke.mjs`: 새 사용자와 사진 바꾸기 창에서 파일 고르기, 그림이 아닌 파일, 공유하기 창의 안내, 짧은 링크 손님의 내 그림
- `tools/css-diff.mjs`, `tools/night-contrast.mjs`: 닉네임 칸을 이름으로 찾음(known-issues 72)
- `docs/requirements.md`, `docs/tasks.md`, `docs/guide.md`, `docs/file-map.md`, `known-issues.md`

## 정한 것과 이유
- 원본 사진을 받지 않고 24×24칸 16색으로 줄였습니다. 사이트의 그림이 모두 픽셀 그림이고, 줄인 그림은 공유 링크에 담을 만큼 작기 때문입니다.
  색은 채널마다 16단계(4096색)에서 골라 색 하나를 12비트로 적습니다. 그 시절 컴퓨터의 팔레트와도 맞습니다.
- 그림은 칸마다 "왼쪽 칸과 같음 1비트, 위 칸과 같음 2비트, 아니면 색 번호"로 적습니다. 윈도우 배경 사진 8장으로 재 보니 16색 그림이 116~237바이트였습니다.
  덧붙임 바이트는 길이를 한 바이트로 적어 255개까지라, 그림은 240바이트까지만 받고 넘으면 색을 하나씩 줄여 다시 만듭니다(1색이면 늘 들어간다).
- 새 형식 번호를 만들지 않고 형식 5의 사진 번호 자리에 255를 적었습니다. 지금 배포된 페이지(`origin/main`의 `src/share.js`)로 새 링크를 풀어 보니
  255를 모르는 사진 번호로 읽고 덧붙임 바이트를 건너뛰어, 사진만 빼고 같은 집으로 열었습니다.
- 긴 링크에는 담지 않았습니다. 200~300자가 늘어 카카오톡의 500자에서 잘리기 쉽습니다(known-issues 57). 긴 링크의 손님에게는 사진을 넣기 전의 링크처럼 이름의 첫 글자를 보입니다.
  다른 사진을 대신 보이면 주인이 고르지 않은 사진이 주인 사진처럼 보여서 첫 글자로 정했습니다.
- 단추 이름은 윈도우에서 파일을 고르는 창을 여는 단추 이름("찾아보기")을 따라 "그림 파일 찾아보기"로 했고, XP의 사용자 그림 고르기처럼 그림 줄 아래에 밑줄 글자로 두었습니다.
- 사진 바꾸기 창에서는 목록 사진처럼 고르자마자 저장합니다. 다른 사진을 누르면 내 그림은 지워지고, 되돌리려면 파일을 다시 고릅니다(사진 값을 하나만 저장한다).

## 남은 일과 알아 둘 것
- 손님에게 보일 그림을 걸러 낼 방법이 없습니다. 팀 회의에서 그대로 둘지 정합니다(requirements의 "아직 정하지 않은 것").
- 그림의 가운데를 자르므로 사람이 한쪽에 치우친 사진은 잘릴 수 있습니다. 자를 자리를 고르게 할지 정합니다.
- 아이폰 사진(HEIC)처럼 크롬이 열지 못하는 파일은 "그림 파일을 열지 못했습니다"라고 알립니다.
- 덧붙임 바이트에 칸을 더할 때는 내 그림 바이트 뒤에 붙입니다. 내 그림이 240바이트일 때 남는 자리는 12바이트입니다.
