# 2026-11-14 라디오 CD에 이름과 색 붙이기 (soomin007)

## 한 일
라디오의 CD마다 주인이 이름과 색을 정할 수 있게 했다. 애플 뮤직 플레이리스트는 표지와 이름을 받아 올 길이 없어서
여러 장을 넣으면 라벨이 모두 "애플 뮤직 플레이리스트"였고 디스크 그림도 같았다. 펼친 CD 아래 라벨은 "애플 뮤직 플레이…"로 잘렸다.
어느 CD가 어느 플레이리스트인지 알 수 없다는 제보가 있었다(화면 사진으로 확인).

## 바꾼 파일
- `src/likes.js`: `radio`가 CD마다 `{ url, name, color }`를 받는다. 이름은 `line()`으로 16자(`LIMIT.cdName`)까지, 색은 1~5번만 남기고 0번(은색)과 빈 이름은 적지 않는다
- `src/apps/radio-app.js`: 넣는 칸에 이름 칸과 색 고르기(`CD_COLORS`), 라디오에 든 CD의 "이 CD 고치기", 디스크의 `data-color`, 펼친 CD와 표시창에 주인이 붙인 이름
- `style.css`: CD 색 여섯 가지(`--cd-face`), 두 줄 라벨(`.cd-name`, 넘칠 때만 `.tight`), 표시창 글자 12px, 색 고르기(`.cd-swatch`)
- `tools/check.py`: `check_cd_colors`가 `LIMIT.cdColors`, `CD_COLORS`, `.cd[data-color]`의 개수가 같은지 본다
- `tools/link-fuzz.mjs`: 무작위 집의 CD에 이름과 색(받지 않는 값 포함)을 넣고, 검사한 CD의 이름 길이, 반쪽 글자, 색 번호, 겹친 링크를 본다
- `tools/smoke.mjs`: 이름 없이 넣으면 안내가 뜨는지, 넣은 이름과 색이 저장되고 보이는지, 다음 CD의 색, 손님 화면의 CD 이름이 글자로만 들어가는지
- `assets/fonts/aga-ui*.woff2`, `aga-ui.txt`: 이름 칸 안내 "16자까지"의 '까'를 넣어 `python tools/ui_font.py`로 다시 만듦
- `docs/requirements.md`(라디오 줄과 정한 것), `docs/guide.md`, `docs/file-map.md`, `docs/tasks.md`, `known-issues.md` 65번

## 정한 것과 이유
- 이름은 펼친 CD 아래 두 줄(124px, 13px 글자)과 라디오 표시창 한 줄에 다 들어가는 16자까지 받는다. 갈무리 글자 폭을 재 보니 13px에서 한글이 13px라
  한 줄에 9자, 두 줄에 16자가 들어간다. 표시창은 14px로는 13자뿐이라 갈무리11이 또렷한 12px로 줄였다(16자가 192px, 칸 안쪽은 198px).
- 받아 올 수 있는 이름(스포티파이 oEmbed, 애플 앨범)은 주소를 넣는 대로 이름 칸에 채운다. 주인이 고쳐 쓴 뒤에는 덮지 않는다.
  이름은 꼭 넣게 했다. 이름을 받을 수 없는 플레이리스트가 이번 제보의 원인이라 비워 두면 같은 문제가 남는다.
  주소를 붙여 넣자마자 넣기를 누르면 받기 전이라서, 그때는 3초까지 기다려 받은 이름을 쓴다.
- 색은 은색, 금색, 파란색, 초록색, 분홍색, 보라색이다. 2000년대에 굽던 색 있는 공CD처럼 무지개 빛을 그 색으로 물들였다.
  새 CD는 다른 CD가 쓰지 않은 색 가운데 앞의 것을 먼저 골라 둔다. 그래서 주인이 색을 고르지 않아도 CD가 서로 달라 보인다.
  책장처럼 무작위로 고르면 앞 CD와만 다르고 그 앞의 CD와는 같을 수 있다. CD 장수(6)만큼 색이 있어서 넣는 칸이 열릴 때는 늘 남는 색이 있다.
- 0번 색과 빈 이름은 저장하지 않아서 이름 칸이 생기기 전의 CD와 그 링크는 바이트까지 그대로다. 옛 CD는 은색이고 받아 온 이름을 쓴다.
  공유 링크는 칸 이름을 줄이는 표(`KEY_SHORT`)에 `name`, `color`가 이미 있어 고칠 것이 없었다. 짧은 링크는 같은 글자를 서버에 두므로 같이 담긴다.
- 고치기는 라디오에 든 CD에만 둔다. "이 CD 지우기"와 같은 자리이고, 고칠 때는 주소를 바꾸지 않는다(다른 CD가 된다).
- 라벨은 띄어쓰기에서 줄을 바꾼다("애플 뮤직 / 플레이리스트"). 그러면 세 줄이 되는 이름이 있어서 그런 라벨에만 글자 사이 줄바꿈을 다시 허용했다(known-issues 65).

  `node tools/night-contrast.mjs` 실패 0개
- 로컬 서버에서 옛 CD 세 장(`{ url }`만)이 든 방을 열어 그대로 뜨는 것, 스포티파이 앨범 주소를 넣으면 이름이 채워지는 것, 이름 칸이 16자에서 멈추는 것,
  옛 플레이리스트 CD를 라디오에 넣고 "이 CD 고치기"로 이름과 색을 붙이면 표시창과 펼친 줄과 저장본이 바뀌는 것, 그 방을 긴 링크로 열어 손님 화면에서 같게 보이는 것을 봤다

## 남은 일과 알아 둘 것
- 색을 늘리면 `LIMIT.cdColors`, `CD_COLORS`, `style.css`의 `.cd[data-color]`를 같이 고친다(자동 점검이 개수를 본다). 색 번호의 순서는 바꾸지 않는다(이미 보낸 링크의 색이 바뀐다).
- CD 이름이 든 방은 긴 링크(`#r=`)가 한글 16자 이름 하나에 70자쯤 길어진다(시험한 방은 CD 네 장에 이름 둘로 335자). 짧은 링크(`#s=`)는 길이가 그대로다.
- 모니터의 디가우스 층(`#degauss`)이 화면(`#screen`) 아래로 107px 넘쳐서, 무언가 요소를 화면 안으로 끌어오는 스크롤(`scrollIntoView`)을 하면 화면 전체가 위로 밀린다.
  시험 도구가 단추를 누를 때 그렇게 밀리는 것을 봤고, 마우스로 누를 때는 생기지 않는다. 이번 일과 따로 볼 거리다.
