# 2026-11-14 모니터 화면이 스크롤되어 밀리지 않게 하기 (soomin007)

## 한 일
라디오 CD 이름 작업(PR 87)을 앱 브라우저로 시험하다가, 단추를 누르면 모니터 화면 안이 통째로 위로 밀려 아래가 검게 비는 것을 봤다.
화면(`.screen`)이 스크롤된 것이었고, 켤 때의 디가우스 층이 일부러 화면보다 크게 깔려 있어서 스크롤할 거리가 생겨 있었다.
화면을 `overflow: hidden` 대신 `overflow: clip`으로 잘라, 무엇이 넘쳐도 스크롤되지 않게 했다(known-issues 66).

## 바꾼 파일
- `style.css`: `.screen`의 `overflow`를 `clip`으로 바꾸고 이유를 주석에 적음
- `tools/smoke.mjs`: 바탕화면에서 `#screen`의 `scrollTop`, `scrollLeft`를 넣어 보고 0으로 남는지 본다
- `known-issues.md` 66번

## 정한 것과 이유
- 디가우스 층(`.degauss`, `inset: -15%`)은 그대로 둔다. 돌고 커지는 색 번짐이 화면 가장자리를 드러내지 않게 하려고 크게 깐 것이라,
  층을 줄이면 연출이 달라진다. 넘치는 층은 앞으로도 생길 수 있어서 화면 쪽에서 막았다.
- clip은 hidden과 달리 새 블록 서식 맥락을 만들지 않는다. `.screen`의 직계 요소(`.crt`, 비네트와 깜빡임 층, OSD)는 모두 절대 위치라 배치가 같다.
- clip은 MDN에서 Baseline 널리 사용 가능이라 사파리와 파이어폭스 확인 조건에 들지 않는다.

## 확인한 것
- 화면 없는 크롬에서 고치기 전에는 화면이 아래로 107px, 오른쪽으로 164px까지 스크롤되었고, 고친 뒤에는 0으로 남는다.
- 애니메이션을 멈추고 같은 화면을 hidden과 clip으로 찍어 견줬다. 꺼진 화면은 픽셀까지 같고, 디가우스 층을 띄운 화면과 로그인 화면은
  화면 둘레의 1,461픽셀만 색 값이 1(255 가운데) 다른 반올림 차이였다.
- `python tools/check.py`, `node tools/smoke.mjs`, `node tools/css-diff.mjs`의 결과는 PR 설명에 적었다.

## 남은 일과 알아 둘 것
- 요소를 보이게 하려고 `scrollIntoView`를 쓰면 화면은 밀리지 않지만, 창 안의 다른 스크롤 상자는 여전히 함께 움직인다.
  TV처럼 그 줄의 `scrollLeft`만 바꾸는 쪽이 안전하다(`src/apps/tv-app.js`).
