# 2026-11-14 계정 프로필 사진 (soomin007)

## 한 일
그 시절 컴퓨터처럼 계정마다 프로필 사진을 고르게 했다(F25, 시험). 사진은 사용자가 올리는 그림 대신 우리가 그린 24×24칸 픽셀 그림
여덟 장(강아지, 고양이, 꽃, 축구공, 기타, 로켓, 케이크, 오리) 가운데 고른다. 새 사용자 만들기에서는 닉네임 칸 위의 사진 줄로 고르고,
바탕화면에서는 시작 메뉴 맨 위의 내 사진을 누르면 뜨는 "사진 바꾸기" 창에서 바꾼다. 고른 사진은 로그인 화면의 내 사용자와 시작 메뉴에 보인다.

## 바꾼 파일
- `data/user-pictures.js`: 사진 여덟 장의 글자 격자, 바탕 색, 글자마다의 색
- `src/user-pictures.js`: 사진 SVG, 크기 맞춤(`fitUserPictures`), 고르는 줄, 사진 바꾸기 창, 내 사진 저장과 고른 적 없는 사용자의 사진 정하기
- `src/login.js`: 새 사용자 만들기의 사진 줄과 왼쪽 큰 사진, 내 사용자 칸의 사진. 사용자 그림(`avatar`)이 사진 id를 받는다
- `src/os.js`: 시작 메뉴 맨 위의 사용자 그림. 내 컴퓨터에서는 사진 단추, 연습 방에서는 보기만 하는 사진, 손님에게는 주인 이름의 첫 글자
- `src/main.js`, `src/config.js`: `fit`에서 `fitUserPictures`를 부르고, 저장 키 `STORAGE_PICTURE`(`agarago.picture`)를 둠
- `style.css`: 로그인 절 끝의 "사용자 사진" 규칙
- `tools/check.py`: `check_user_pictures`(줄 수와 칸 수, colors에 없는 글자, id)
- `known-issues.md` 68번, `tools/check.py`의 `check_feature_numbers`: 같은 날 다른 작업이 F23, F24를 먼저 써서 번호를 두 번 고친 일과, 기능 번호가 겹치면 알리는 점검
- `tools/smoke.mjs`: 사진 고르기, 로그인 화면과 시작 메뉴의 사진, 사진 바꾸기 창, 연습 방과 손님의 시작 메뉴, 초기화의 사진 지우기
- `tools/night-contrast.mjs`: 사진 바꾸기 창도 열어 잰다. 그래서 `AGENTS.md`, `docs/checklists.md`의 대비 점검 설명도 고침
- `docs/requirements.md`, `docs/tasks.md`, `docs/guide.md`, `docs/file-map.md`
- `assets/fonts/aga-ui*.woff2`, `aga-ui.txt`: 사진 이름과 창 제목의 새 글자를 넣어 작은 글꼴을 다시 만듦

## 정한 것과 이유
- 실제 윈도우의 사용자 사진은 마이크로소프트의 그림이라 쓰지 않았다. 그 시절 사용자 사진처럼 동물과 물건을 고르고,
  바탕화면 아이콘과 같은 글자 격자와 재료 색 겉선으로 그렸다. 아이콘과 달리 사진은 바탕을 꽉 채우고, 작게 보여도 구별되게 사진마다 바탕 색을 다르게 했다.
- 사진은 집(`agarago.home.v3`)에 넣지 않고 `agarago.picture`에 id만 따로 둔다. 집은 공유 링크에 담기고 연습 방이 바꿔 끼우는 값이라,
  집에 넣으면 링크 검사(`src/share.js`)를 같이 고쳐야 하고 연습 방에서 샐 길도 생긴다. 따로 두니 초기화의 `agarago.` 키 지우기가 사진까지 지운다.
- 사진이 생기기 전에 만든 사용자는 닉네임으로 여덟 장 가운데 한 장을 정해 보여 준다. 저장하지 않지만 같은 닉네임이면 늘 같은 사진이다.
  새 사용자에게는 그 시절 컴퓨터처럼 아무 사진이나 한 장을 미리 골라 두어, 고르지 않고 확인을 눌러도 된다.
- 링크로 온 친구 집과 이웃집은 사진을 모르므로 지금처럼 이름의 첫 글자를 둔다. 로그인 화면에서 이 컴퓨터의 주인이 누구인지도 구별된다.
- 바꾸는 곳은 시작 메뉴 맨 위의 사진으로 정했다. XP도 시작 메뉴의 사진을 누르면 사진을 고르는 창이 열렸다.
  로그인 화면의 사진은 눌러서 들어가는 자리라 따로 단추로 만들지 않았다. 창에서 사진을 누르면 바로 저장되므로 확인 단추 없이 닫기만 둔다.
- 연습 방에서는 시작 메뉴의 사진을 보기만 한다. 연습에서 한 일은 남기지 않는다는 규칙(known-issues 40)을 지키는 가장 간단한 길이다.
- 크기는 아이콘의 `fitPixelIcons`처럼 한 칸이 화면 픽셀 정수 개가 되게 고른다(known-issues 67). 두 자리를 따로 고르면
  1366×768(배율 0.61)과 1440×900의 200%에서 왼쪽 큰 사진과 고르는 줄의 사진이 같은 크기로 나와서, 큰 사진은 고르는 줄보다 한 칸이
  화면 픽셀 하나 이상 굵은 크기에서 고르고 원래 크기의 1.8배까지 커질 수 있게 했다. 사진 바꾸기 창은 열 때의 사진 크기로 창 크기를 정한다.
- 같은 때 다른 작업이 `src/icons.js`를 고치고 있어서, `fitUserPictures`는 `fitPixelIcons`와 같은 계산을 따로 둔다.

## 확인한 것
- 화면 없는 크롬으로 1366×657, 1280×600, 1440×790의 200%, 1536×730의 125%, 1920×960, 2560×1300에서 찍어 보았다.
  로그인 화면, 새 사용자 만들기, 시작 메뉴, 사진 바꾸기 창의 사진 한 칸이 모두 정수 픽셀(1, 2, 3)이었고, 큰 사진이 고르는 줄보다 컸다.
  창은 넘치지 않았고 고르는 줄은 한 줄에 들어갔다. 1024×500(배율 0.46)에서는 고르는 줄의 사진만 부드럽게 줄어든다.
- 밤 모드에서 사진 바꾸기 창과 시작 메뉴의 사진을 보았다.
- `python tools/check.py` 오류 0개, `node tools/smoke.mjs` 200개 모두 통과, `node tools/night-contrast.mjs` 실패 0개.

## 남은 일과 알아 둘 것
- 공유 링크로 온 손님에게 주인 사진을 보여 주려면 링크에 사진을 담는다. 짧은 형식은 머리 바이트 4 뒤에 주인 이름, 인사말, 공간 수가
  차례로 놓여서 칸을 끼우면 옛 링크와 헷갈린다. 새 머리 바이트 5를 두고 인사말 다음에 사진 번호 1바이트를 넣고(옛 4 링크는 사진 없이 연다),
  예전 형식(`encodeJson`)에는 짧은 키 하나를 더한다. `sanitizeHome`은 `USER_PICTURES`에 있는 id만 남기고, 링크를 만들 때 `ownPicture()`를 읽어 넣는다.
  그 뒤 로그인 화면의 친구 집 칸(`login.js`의 `userTile`)과 손님 시작 메뉴(`os.js`의 `openStartMenu`)에 그 사진을 넘긴다.
  링크 형식을 바꾸므로 `node tools/link-fuzz.mjs`의 `randomHome`과 `invariants`에도 더한다. 이웃집은 `data/neighbors.js`에 사진 칸을 두는 길도 있다.
- 사진을 더할 때는 `data/user-pictures.js` 끝에 한 장을 더하고 있던 id는 바꾸지 않는다(저장된 사진을 id로 찾는다).
  고르는 줄은 여덟 장이 한 줄에 들어가게 창 폭을 정했으니, 더 늘리면 창 폭과 새 사용자 칸이 몇 줄이 되는지 다시 본다.
- 아이콘 작업이 끝나면 `fitUserPictures`와 `fitPixelIcons`의 계산을 한곳으로 모을 수 있다.
