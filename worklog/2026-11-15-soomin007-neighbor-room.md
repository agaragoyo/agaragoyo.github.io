# 2026-11-15 이웃집에 Admin의 방 넣기 (soomin007)

## 한 일
이웃집(F19) 목록에 Admin의 방을 link 줄로 넣었다. 그 방의 링크를 만든 사용자의 닉네임이 문패에 쓰기 어려운 이름이라,
이름 바꾸기(F28)를 먼저 만들고 배포 사이트에서 닉네임을 soomin007로 바꾼 뒤 서버의 방(`homes/ZUMveoKX`)을 받아 주인 이름이 같은지 확인했다.
link 줄이 실제 목록에 들어간 것은 이번이 처음이다.

같이 이웃집의 이름이 서버의 방 주인 이름을 따르게 바꿨다. 지금까지는 목록의 이름을 썼다.
그래서 이웃집 주인이 닉네임을 바꾸면 목록을 고치는 PR이 합쳐질 때까지 손님에게 예전 이름이 보였고, 주인의 놀이터에는 자기 집 문패가 하나 더 생겼다.

## 바꾼 파일
- `data/neighbors.js`: Admin의 방을 관리인 앞에 넣고, 머리 주석에 이름이 서버를 따른다는 것을 적었다
- `src/neighbors.js`: link 이웃집은 받은 방의 주인 이름을 쓴다(`toHome`). 놀이터 문패에 쓰고 주인 이름과 견주는 이름도 지금 보일 이름(`shownName`)이고, 놀러 가기 창은 받은 집의 이름을 쓴다
- `src/login.js`: 로그인 화면의 이웃집 자리가 방을 받은 뒤 서버의 주인 이름을 쓴다
- `tools/smoke.mjs`: 받은 뒤 로그인 화면과 문패, 놀러 가기 창에 서버의 이름이 보이는지, 서버의 이름과 같은 주인의 놀이터에서 그 문패가 빠지는지 본다.
  레포의 목록에 든 link 이웃집에도 가짜 서버가 답하게 했다
- `docs/requirements.md`, `docs/tasks.md`, `docs/guide.md`, `docs/file-map.md`, `known-issues.md`(78의 규칙)

## 정한 것과 이유
- 이름을 서버에 맞출지는 Admin에게 두 방법(서버의 이름을 따름, 지금처럼 목록의 이름)을 보이고 고른 대로 했다.
  방의 가구와 글은 이미 서버를 따라 바뀌어서, 이름만 목록에 묶어 둘 까닭이 적다.
- 목록의 이름은 방을 받는 동안의 "불러오는 중" 자리에만 보인다. 넣을 때 링크를 만든 사용자의 닉네임이 목록의 이름과 같아야 한다는 규칙은 그대로 둔다.
  서버의 방은 누구나 읽을 수 있어서, 실명이 아닌지 보는 자리는 넣을 때뿐이다.
- room 줄(예전 긴 링크)은 링크 속 이름이 보낸 때에 멈춰 있어서 목록의 이름을 그대로 쓴다. `tools/check.py`가 둘이 같은지 본다.
- 목록에 실제 link 줄이 생겨서, 눌러 보기 점검의 이웃집 칸은 가짜 서버가 그 방에도 답하게 했다. 답하지 않으면 서버에 방이 없는 집처럼 빠져서 문의 수가 어긋난다.
  서버에 방이 없을 때의 점검은 목록의 link 줄 수만큼 빠지는지 본다.

## 남은 일과 알아 둘 것
- 이웃집 주인이 닉네임을 바꾸면 화면은 저절로 바뀌지만 `data/neighbors.js`의 `name`은 그대로다. 방을 받기 전에 잠깐 보이는 이름이라, 다음에 이 파일을 고칠 때 맞춰 둔다.
- 로그인 화면에서는 이웃집 주인에게도 자기 집의 이웃집 자리가 보인다. 내 컴퓨터(꾸미기)와 이웃집 구경하기(손님)는 가는 곳이 달라서 그대로 두었다.
- 이름 바꾸기가 찾기 어렵다는 지적이 있어, 시작 메뉴에 "이름 바꾸기" 한 줄과 사진 바꾸기 창의 단추를 더하는 일을 다음 PR에서 한다.
- 로컬 서버에서 진짜 서버의 방을 받아 로그인 화면의 자리(로켓 사진), 놀이터 문패, 놀러 가기 창, 손님 시작 메뉴에 soomin007이 나오는지 봤다.
