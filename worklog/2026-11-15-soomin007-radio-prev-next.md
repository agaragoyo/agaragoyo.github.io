# 2026-11-15 라디오 유튜브 재생목록의 이전 곡, 다음 곡 단추 (soomin007)

## 한 일
유튜브 재생목록을 CD로 넣으면 곡을 하나씩 넘길 방법이 없다는 제보가 있었다. 음악 창의 플레이어 아래에 "이전 곡"과 "다음 곡" 단추를 달았다.
단추는 유튜브 재생목록 CD를 틀 때만 보이고, IFrame Player API의 `previousVideo()`와 `nextVideo()`를 부른다.
영상 하나짜리 유튜브 CD와 스포티파이, 애플 뮤직 CD에는 단추가 없다. 음악 창에서 CD를 바꾸면 단추도 그 CD에 맞게 나타나고 사라진다.

## 바꾼 파일
- `src/apps/radio-app.js`: 음악 창에 단추 줄(`.radio-player-skips`)을 더했다. `hasTracks`가 재생목록 CD인지 가리고, `syncSkips`가 플레이어가 준비되었고 오류가 없을 때만 단추를 켠다.
  `fit()`이 창 높이에 단추 줄을 더하고, `watchYouTube`는 API 스크립트를 받지 못할 때 부르는 `onLost`를 새로 받는다. 오류 알림은 지금 떠 있는 플레이어의 것일 때만 받는다
- `style.css`: 단추 줄과 `[hidden]` 짝 규칙, 쉬는 단추의 모양(`.radio-player-skips .btn:disabled`)
- `tools/smoke.mjs`: 유튜브 API를 가짜(`fakePlayer`)로 바꿔 끼워 단추가 보이고 숨는 때, 쉬는 때, 보내는 명령, 창 높이, 안내 줄이 잘리지 않는지를 본다. 가짜 oEmbed가 스포티파이에도 답한다
- `docs/guide.md`(라디오 절), `docs/requirements.md`(F12의 라디오 줄과 정한 것), `docs/tasks.md`, `docs/file-map.md`

## 정한 것과 이유
- 자리는 라디오 그림이 아니라 음악 창의 플레이어 바로 아래다. 라디오 그림의 가운데 줄은 폭이 220px인데 ▶ ■ ⏏ 세 개가 168px을 차지해서
  단추 둘(각 85px)과 사이 간격을 합친 178px이 들어갈 자리가 없다. 그 아래 `.radio-tools` 줄은 주인이 CD를 넣고 고치는 줄이라 손님에게는 비어 있고, 곡 넘기기와 성격도 다르다.
  음악 창은 라디오를 내려놓은 뒤에도 남고 친구 집 배경음악(`home-bgm`)이 저절로 연 창도 같은 창이라, 음악이 나오는 동안 어디서든 곡을 넘길 수 있다
- 크기는 기존 라디오 단추(`.radio-tools .btn`)와 같은 `.btn`이다. 글씨 16px, 높이 36px이고 폭은 "이전 곡"과 "다음 곡" 모두 85px이다(기존은 "CD 넣기" 91px, "이 CD 고치기"와 "이 CD 지우기" 130px).
  단추 줄은 348×44px로 위 여백 8px, 단추 36px이고 단추 사이는 8px, 왼쪽 여백은 안내 줄과 같은 10px이다. 안내 줄은 그 아래(한 줄 35px, 오류일 때 두 줄 56px)에 그대로 있다
- 창 높이는 단추 줄 44px만큼 늘어 326px이 되었다(영상 CD 282px, 오류 안내가 두 줄이면 347px). 플레이어는 348×200px 그대로이고 단추는 그 아래 줄이라 플레이어 위에는 아무것도 겹치지 않는다.
  유튜브 API 서비스의 최소 기능 요건은 플레이어를 200×200px보다 작게 띄우지 말라는 것과 플레이어 앞에 다른 요소를 두지 말라는 것을 정하고(2026-11-15에 다시 읽음),
  플레이어 밖의 단추로 곡을 넘기는 것에는 따로 정한 말이 없다. 단추가 부르는 `previousVideo()`와 `nextVideo()`는 IFrame Player API 문서에 있는 함수다
- 준비되기 전과 오류가 난 뒤에는 단추를 숨기지 않고 쉬게 둔다(눌러도 일어나는 일이 없다). 숨기면 플레이어가 뜬 뒤 1~2초 만에 단추 줄이 생기면서 창이 44px 커져 화면이 움직인다.
  쉬는 단추는 바탕 `#e6e3d9`에 글자 `#5f5a4d`(5.4:1)로 평평하게 그려 켜진 단추와 구별한다. 오류가 나면 안내가 "이 재생목록은 여기서 재생할 수 없습니다"라서 단추도 같이 쉰다
- 유튜브의 API 스크립트를 받지 못하면(막았거나 연결이 끊겼다) 재생목록 CD에서도 단추를 거둔다. 플레이어는 돌지만 명령을 보낼 길이 없어서 영영 쉬는 단추를 보여 주지 않으려는 것이다
- 이름은 결과를 말하는 "이전 곡", "다음 곡", 툴팁은 명사형 "재생목록의 이전 곡"과 "재생목록의 다음 곡"(10자)이다(`AGENTS.md`의 말투 표)
- 첫 곡에서 이전 곡, 마지막 곡에서 다음 곡은 막지 않고 유튜브가 하는 대로 둔다(아래 확인한 것). 양 끝에서 단추를 쉬게 하려면 `getPlaylistIndex()`와 `getPlaylist()`를 계속 읽어야 해서 이번에는 넣지 않았다

## 확인한 것
- `python tools/check.py` 오류 0개(경고 둘은 원래 있던 라디오와 침대 그림), `node tools/smoke.mjs` 실패 0개(407개), `node tools/night-contrast.mjs` 실패 0개
- 새 검사가 걸러내는지 보려고 여섯 군데를 일부러 틀린 사본으로 smoke를 돌렸다. 영상 CD에도 단추가 뜸, 처음부터 켜진 단추, API 스크립트를 받지 못해도 단추가 남음,
  `fit()`이 단추 줄을 빼먹음, `[hidden]` 짝 규칙이 없음, 오류가 난 뒤에도 켜진 단추다. 새 검사 가운데 10개와 기존 검사 하나가 실패했고, 여섯 가지 모두 하나 이상의 검사에 걸렸다.
  이때 `fit()`을 틀리면 플레이어가 200px에서 170px로 줄어든다는 것을 처음 보아서 iframe에 `flex: none`을 두고 known-issues 81번을 썼다.
  `flex: none`을 둔 사본에서는 같은 잘못이 플레이어 200px 그대로, 안내 줄이 창 아래로 잘리는 것으로 나타났고 `noteFits` 검사가 그것을 잡는다
- 진짜 유튜브에서 곡이 넘어가는지 localhost(화면 없는 크롬)로 봤다. 공개 재생목록 `PLBB231211A4F62143`(29곡)을 라디오에 CD로 넣고, 앱의 방식(iframe 주소에 `list=`를 넣은 뒤 API를 붙임)으로 음악 창을 띄워
  진짜 마우스로 단추를 눌렀다. 앱이 만드는 `YT.Player`를 감싸 `getPlaylistIndex()`와 상태와 재생 시각을 읽었다
  - 단추는 창이 열리고 1.3~1.8초 뒤에 켜졌다. 그때 `getPlaylist()`에는 이미 29곡이 있었고, 켜지자마자(첫 곡이 아직 버퍼링 중일 때) 눌러도 다음 곡으로 넘어갔다
  - 다음 곡은 0번에서 1번, 2번으로, 이전 곡은 2번에서 1번으로 갔다. 곡이 6초쯤 흐른 뒤에 이전 곡을 눌러도 그 곡을 처음부터 다시 틀지 않고 앞 곡(1번에서 0번)으로 갔다
  - 첫 곡(0번)에서 이전 곡: 0번 그대로 첫 곡이 처음부터 다시 나왔다(상태가 2, -1, 3, 1로 바뀌고 재생 시각이 0으로 돌아감). 이 동작은 API 문서가 말한 것과 같다
  - 마지막 곡(28번)에서 다음 곡: 28번 그대로 마지막 곡이 처음부터 다시 나왔다. 두 번의 측정에서 두 번씩 눌러 모두 같았고, 끝났다는 상태 0은 오지 않았다. 문서는 연속 재생이 아니면 재생이 끝난다고 쓰는데 다르다
  - 마지막 곡에서 이전 곡은 27번으로 갔다. 둘째 측정에서는 다른 점검이 같이 돌아 곡이 버퍼링에서 오래 멈춰 그 구간의 재생 시각은 믿지 않고 곡 번호만 봤다. 페이지 오류와 콘솔 오류는 없었다
- 진짜 유튜브가 막는 재생목록(제보된 재생목록, 플레이어 오류 150)을 같은 방법으로 틀었다. `onReady`가 오고 1ms 뒤에 `onError`(150)가 왔고, 단추는 처음부터 끝까지 쉬는 단추였고 안내는 오류 안내로 바뀌었다(창 347px)
- 단추 크기와 자리는 가짜 플레이어를 붙인 화면에서 쟀다(화면 1440×900, 낮과 밤). 낮과 밤의 계산된 색이 같다. 켜진 단추 글자 `#2a1f18`은 단추 바탕의 가장 어두운 끝 `#d6d0c5`와 10.5:1,
  쉬는 단추 글자 `#5f5a4d`는 `#e6e3d9`와 5.4:1, 안내 글자 `#e6e1d6`은 창 바탕 `#111`과 14.5:1이다. `night-contrast`는 음악 창을 열지 않으므로 이 값은 직접 쟀다
- 가구 가까이 보기의 라디오 화면(음악 창이 열려 왼쪽으로 비킨 모습)은 고치지 않았다. 음악 창은 높이만 44px 늘었고 바탕화면 안에 든다(위 72px, 아래 끝 398px쯤, 라디오 화면과 겹치지 않는다)

## 남은 일과 알아 둘 것
- 제보된 재생목록은 지금 비공개로 보여서(오류 150) 이 단추를 써 보지 못했다. 공개로 바꾸면 위와 같이 넘어가는지 한 번 눌러 본다
- 첫 곡에서 이전 곡, 마지막 곡에서 다음 곡은 그 곡을 처음부터 다시 틀 뿐 쉬지 않는다. 양 끝에서 단추를 쉬게 하거나 한 바퀴 돌게 하려면 `getPlaylistIndex()`와
  `getPlaylist().length`를 상태가 바뀔 때마다 읽어야 한다. 마지막 곡의 다음 곡이 끝나지 않는 것은 문서와 다르므로 그 동작에 기대는 기능을 만들 때는 다시 잰다
- `tools/night-contrast.mjs`는 음악 창(재생목록 CD)을 열지 않는다. 이 창의 색을 고칠 때는 위 값을 다시 재거나 도구에 한 단계를 더한다(가짜 `window.YT`가 필요해 이번에는 더하지 않았다)
