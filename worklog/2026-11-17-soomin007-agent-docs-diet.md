# 2026-11-17 AI 도구가 시작할 때 읽는 문서 줄이기 (soomin007)

## 한 일
모든 작업 전에 읽는 `AGENTS.md`와 `known-issues.md`가 3주 사이에 2.5배, 13배로 불어 있었다.
다른 문서에 이미 있는 절을 `AGENTS.md`에서 걷어 내고, known-issues 제목에 영역 태그를 달아 세션이 자기 영역의 항목만 고르게 했다.
없어진 기능에서 생긴 함정 10개는 보관 파일로 옮겼다.

## 바꾼 파일
- `AGENTS.md`: 10,443자에서 7,208자로 줄였다. "새 기능을 붙이는 곳"은 파일 지도에 합치고 한 줄 안내만 남겼고, "실행과 확인"은 고친 곳과 돌릴 도구를 짝지은 표로 줄였다.
  "작업 시작 전"은 큰 문서를 grep으로 필요한 절만 읽는 순서로 바꿨다. 손님 화면에 뜨는 글의 보안 규칙(`h()`, `safeLink`, `decodeHome`)은 "지켜야 할 것"으로 올렸다.
  "팀에서 정하는 중"은 `docs/requirements.md`에 같은 내용이 있어 뺐다
- `known-issues.md`: 맨 위에 영역 태그 표(9개)와 쓰는 형식을 두고 남은 82개 제목에 태그를 달았다. 93번(이 일)을 더했다
- `docs/known-issues-archive.md`: 새 파일. 볼록 화면, 1998과 2010, 시대 덮어쓰기에서 생긴 5, 9, 13, 18, 19, 21, 29, 30, 39, 41번
- `docs/file-map.md`: "자주 찾는 것"에 `AGENTS.md`에만 있던 내용(기본 앱 만들기, 서버에 둘 것, `SANITIZE`, `LINK_CODES`는 끝에만, 실험실에 넣을 것)을 합치고 보관 파일 줄을 더했다
- `tools/check.py`: `check_known_issues`를 더했다. 제목의 태그가 맨 위 표에 있는지, 번호가 보관 파일과 겹치지 않는지, 93번부터 800자를 넘지 않는지 본다
- `docs/tasks.md`: 끝난 할 일 한 줄이 가리키던 known-issues 30번을 보관 파일 주소로 고쳤다

## 정한 것과 이유
- 지난 3주 AI 세션 31개의 기록을 재 보니 시작 문서가 차지한 몫은 입력 사용량의 4.5% 정도였다.
  그래서 줄이는 이유는 사용량보다 관계없는 규칙 사이에 필요한 규칙이 묻히는 것과 문서가 불어나는 속도에 두었다.
  Claude Code 문서도 지침 파일이 길수록 덜 지켜진다며 코드 일부에만 드는 지시는 따로 두라고 권한다.
- known-issues를 영역별 파일로 쪼개지 않았다. 코드 주석과 도구가 항목을 번호로 부르고 여러 문서가 파일 이름을 전제해서, 태그를 다는 것보다 얻는 것이 적다.
- 번호는 그대로 두고 보관 파일과 이어 쓴다. 코드 주석의 "known-issues 18" 같은 번호도 두 파일을 grep하면 찾을 수 있다.
- 말투 표와 "지켜야 할 것"은 거의 모든 PR에 들어서 `AGENTS.md`에 그대로 뒀다.
- 지금 있는 긴 항목은 줄이지 않았다. 길이 제한은 새 항목(93번부터)에만 건다.

## 남은 일과 알아 둘 것
- 새 항목에 태그를 빼거나 표에 없는 태그를 쓰면 `python tools/check.py`가 오류로 알린다. 맞는 태그가 없으면 맨 위 표에 한 줄을 더한다.
- 같은 날 나란히 작업하면 known-issues 번호가 겹칠 수 있다. 이제 점검이 겹친 번호를 잡으므로, 합치기 전에 main을 받아 비어 있는 다음 번호로 고친다.
- Claude Code만 읽는 경로별 규칙(`.claude/rules/`)은 한 영역에서 같은 실수가 되풀이될 때 그 영역부터 붙여 보기로 하고 이번에는 하지 않았다.
