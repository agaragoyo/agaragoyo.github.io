# 2026-11-24 배포 작업을 올리기와 배포로 나누기 (soomin007)

## 한 일
책장 글자 수 한도(PR 182)를 합친 뒤 배포가 여섯 번 이어서 실패했다. 사이트 코드가 아니라, 묶음 올리기와 배포를 한 job에서 이어 하는 배포 작업의 구조가 원인이었다.
`pages.yml`을 올리기(build)와 배포(deploy) 두 job으로 나눴다.

## 바꾼 파일
- `.github/workflows/pages.yml`: `build`(지문 찍기와 묶음 올리기)와 `deploy`(배포, `needs: build`). 쓰는 액션의 판과 권한, 켜지는 때는 그대로다
- `docs/file-map.md`, `known-issues.md`(120)

## 정한 것과 이유
- 이날 첫 시도 일곱 번 가운데 여섯 번은 묶음을 올린 지 0.8초쯤 뒤에 찾아 0개였고, 다시 돌리기 네 번 가운데 두 번은 앞 시도의 묶음까지 두 개로 잡혔다. githubstatus는 정상이었다.
- actions/deploy-pages 저장소의 이슈 451이 같은 증상이다. 2026-10-07에 열렸고 2026-11-22에 부쩍 잦아졌다는 댓글이 있다. 올리기를 앞 job으로 옮겨 풀었다고 적혀 있고,
  deploy-pages의 설명서도 배포를 따로 떼어 낸 job에 두라고 권한다. 새 판(deploy-pages v5.0.1)에도 이 문제를 고친 것은 없어 판은 올리지 않았다.
- job이 바뀌는 동안 몇 초가 지나 묶음이 보일 틈이 생긴다. 그래도 실패하면 배포 job만 다시 돌릴 수 있어 묶음이 하나로 남는다.
- 기다리는 단계(`sleep`)를 넣는 방법은 몇 초면 되는지 정할 근거가 없고, 다시 돌릴 때 묶음이 둘이 되는 문제가 남아서 쓰지 않았다.
- 묶음 이름에 시도 번호를 붙이는 방법은 모두 다시 돌리기까지 막아 주지만, 배포 job만 다시 돌릴 때 이름을 따로 넘겨야 해서 쓰지 않았다.

## 남은 일과 알아 둘 것
- 실행을 모두 다시 돌리면(`--failed` 없이) 묶음이 둘이 되어 배포가 실패한다. 그때는 Actions 화면의 Run workflow로 새 실행을 켠다.
- 합쳐졌다고 배포된 것은 아니다. 실행의 결론과 배포 주소의 파일 글자를 둘 다 본다.
