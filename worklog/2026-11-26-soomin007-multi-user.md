# 2026-11-26 한 브라우저에 사용자 여럿 두기 (soomin007)

## 한 일
한 브라우저에 사용자를 다섯 명까지 두고, 로그인 화면에서 다른 사용자 칸을 누르면 비밀번호 없이 바로 그 사용자로 바꿔 들어가게 했다(F37).
한 브라우저에서 아이디 둘을 바로 바꿔 쓰고 싶다는 요청이 있어 설계 단계에서 세 방법을 견줬고, 서랍 방법의 동작과 아이디 칸 방법의 모양을 합쳐 쓰기로 정했다.
다른 아이디로 로그인하거나 새 사용자를 만들면 앞 사용자를 지우지 않고 서랍에 넣고, 다른 사용자 무리 아래의 "사용자 지우기"로 서랍의 사용자를 지운다.

## 바꾼 파일
- `src/user-drawers.js`: 새 파일. 앉지 않은 사용자의 키를 `agarago.users` 한 값에 넣고 꺼내는 바꿔 끼우기, 중간에 꺼졌을 때 마저 하기, 로그인 화면에 보일 요약
- `src/home-store.js`: 지우는 키와 서랍에 넣는 키를 `userKeys` 하나로 모으고, 서랍을 지우지 않게 `KEEP`에 더함. 받은 방은 집을 맨 나중에 씀
- `src/login.js`: 내 사용자 아래 글자 단추 셋, 다른 사용자 무리(`othersGroup`)와 사용자 지우기, 칸을 눌러 바꿔 들어가기(`switchTo`), 내 사용자를 지운 뒤 다른 사용자 앉히기
- `src/sign-in.js`: 다른 아이디로 로그인하면 앞 사용자를 서랍에 넣고 받기, 서랍에 있는 계정이면 그 서랍으로 바꾸기, 서랍의 사용자 지우기(`askRemove`), 기다리는 동안 로그인 화면 잠그기
- `src/neighbors.js`: 서랍의 사용자들이 올린 방도 이웃집과 최근에 놀러 간 집에서 빼고, 서랍의 방 번호로 고정한 집인지 보는 `pinnedRoom`
- `src/os.js`, `src/tutorial.js`: 부팅할 때 `resumeSwap`, `takeSeat`가 튜토리얼 진행도 다시 읽음
- `src/user-pictures.js`: 저장해 둔 값으로 사진을 정하는 `pictureOf`
- `src/config.js`: `STORAGE_USERS`, `STORAGE_DRAWER`, `MAX_USERS`. 이 파일만 줄 끝이 CRLF와 LF로 섞여 있어 바꾼 줄만 바이트로 넣었다
- `style.css`: 다른 사용자 칸과 무리 제목, 지우기 단추, 내 사용자 아래 글자 단추 묶음, 왼쪽 단 위 여백 36px에서 24px(시안)
- `tools/smoke.mjs`: 로그인 절의 "지우고 로그인" 점검을 서랍 동작으로 바꾸고 사용자 서랍 절을 더함
- `docs/requirements.md`, `docs/guide.md`, `docs/file-map.md`, `docs/tasks.md`, `known-issues.md`(131~133)

## 정한 것과 이유
- 앉은 사용자는 지금 키를 그대로 쓰고 앉지 않은 사용자만 서랍에 넣었다. 키 이름을 사용자마다 바꾸면 SDK(`AGA.save`)와 팀원 앱, 링크 형식까지 고쳐야 한다.
- 서랍과 "바꾸는 중" 표시를 한 값에 같이 쓴다. 따로 쓰다 그 사이에 꺼지면 같은 사용자가 앉은 자리와 서랍에 둘 다 남는다(known-issues 132).
  새 사용자 만들기와 로그인처럼 서랍에서 꺼내지 않고 새로 들이는 일은 표시를 `new`로 두고, 꺼지면 반쯤 만든 사용자를 지우고 앞 사용자를 다시 앉힌다.
- 사용자마다 서랍 번호(`agarago.drawer`)를 하나 둔다. 서랍의 사용자를 지우다 서버에 닿지 못하면 앞 사용자를 다시 앉히는데, 번호가 바뀌면 "지우기"를 다시 누를 수 없었다.
- 서랍의 사용자를 지울 때 서버에 할 일이 있으면 그 사용자를 잠깐 앉혀 지금의 검사(`blocked`, `unshare`)를 그대로 쓴다. 그동안 로그인 화면은 `inert`로 잠근다.
  잠그지 않으면 기다리는 사이에 내 사용자 칸을 눌러 앞 사용자의 집을 잠깐 앉은 사용자의 키에 저장할 수 있다.
- 다른 사용자가 있으면 비밀번호가 없는 사용자의 "이 컴퓨터 초기화"를 "이 컴퓨터에서 지우기"로 쓴다. 그 사용자 한 명만 지우므로 초기화라는 말이 결과와 맞지 않는다(known-issues 130). 확인 줄에는 누구의 것인지 적는다.
- 내 사용자를 지우면 가장 최근에 쓴 다른 사용자를 같은 일 안에서 앉힌다. 로그인 화면을 그릴 때 앉히면 다른 탭이 바꾸는 중인 것과 겹칠 수 있다.
- 최근에 놀러 간 집은 설계 노트의 기본값대로 사용자마다 두었다. 이미 사용자의 키라 서랍을 따라다니고, 로그인 화면에는 마지막에 쓴 사용자의 것이 보인다.
- 사용자 다섯 명이면 왼쪽 단이 가운데 띠에 거의 닿아 글자 단추 사이를 시안의 6px에서 3px로, 작은 칸의 위아래 여백을 6px에서 5px로 줄였다. 지우기를 고르는 동안에는 내 사용자 아래 글자 단추를 숨긴다.
  1920×1080(100%)에서 고르는 사진 크기를 끼워 잰 왼쪽 단은 평소 648px, 지우기 확인까지 뜬 때 642px다(띠 660px, known-issues 133).

## 남은 일과 알아 둘 것
- 같이 쓰는 컴퓨터에서는 이제 다른 아이디로 로그인해도 앞 사용자가 남는다. 새 기능 안내 창이 "다 쓴 뒤 이 컴퓨터에서 지우기"를 알리지만, 원하는 사용자만 비밀번호로 잠그는 선택(넷플릭스 프로필 잠금)은 아직 없다.
- 팀원 앱(iframe)은 SDK로 저장소에 바로 쓰므로, 다른 탭에서 사용자를 바꾼 직후 그 탭의 게임이 끝나 기록을 남기면 새 사용자의 키에 들어갈 수 있다. 이전에도 있던 일이고 로그인 화면으로 돌아가면 창이 닫힌다.
- 진짜 서버에는 쓰지 않았다. 서랍의 사용자 지우기와 다른 아이디로 로그인은 가짜 서버(`fakeCloud`)로만 눌러 보았다.
- 확인: `python tools/check.py` 오류 0개, `node tools/smoke.mjs` 1364개 가운데 실패 0개(사용자 서랍 절과 고친 로그인 점검으로 46개가 늘었다), `node tools/link-fuzz.mjs` 실패 0개, `node tools/night-contrast.mjs` 실패 0개.
  `node tools/css-diff.mjs --base=origin/main`은 화면 180가지에서 다른 곳이 로그인 화면 왼쪽 단의 요소(단 높이, 위 여백, 글자 단추 묶음, 새 무리)뿐이고 재지 못한 선택자 0개다.
  바탕화면 같은 다른 화면에도 같은 68곳이 나오는 것은 숨긴 로그인 화면이 페이지에 남아 있어서다. `css-diff`에는 다른 사용자 무리와 사용자 지우기 확인 화면을 더했다.
- 미리보기에서 다섯 명을 심어 바꿔 들어가기, 새 사용자 만들기, 서랍 지우기, 튜토리얼이 사용자를 따라가는지, 바꾸다 멈춘 표시를 손으로 남긴 뒤 다시 켜기를 눌러 보았다.
