# 작업 일지

여러 사람이 같이 만드는 동안 "왜 이렇게 했지?"를 나중에 찾을 수 있도록, 작업 한 덩어리마다 일지를 한 편씩 남깁니다.
보통 Pull Request 하나에 일지 한 편이고, 같은 PR 안에 같이 커밋합니다. 코드를 직접 짰든 AI에게 맡겼든 똑같이 씁니다.

파일 이름은 `날짜-GitHub아이디-주제.md`로 짓고, 영어 소문자와 숫자, 하이픈만 씁니다
(예: `2026-11-03-soomin007-sand-dig.md`). 한 사람이 한 파일만 만들기 때문에 서로 같은 파일을 고칠 일이 없고,
한글 파일 이름이 맥과 윈도우에서 다르게 저장되는 문제도 피할 수 있습니다.
같은 날 같은 주제로 이어서 작업했다면 새 파일을 만들지 않고 원래 파일 아래에 덧붙입니다.

이 레포는 공개입니다. 일지에는 누구에게 보여도 괜찮은 작업 이야기만 씁니다.
팀원에게 물어볼 질문, 누가 무엇을 좋아했는지 같은 팀 안의 이야기, 사적인 이야기는 단톡방이나 개인 메모에 둡니다.

아래 틀을 복사해서 씁니다. 짧게는 10줄, 길어도 60줄 정도면 충분합니다. 코드 자체나 대화 내용은 옮겨 적지 않습니다.

```markdown
# 2026-11-03 모래 파기 미니게임 (soomin007)

## 한 일
무엇을 왜 했는지 두세 문장으로 씁니다.

## 바꾼 파일
- `apps/sand-dig/index.html`: 새 미니게임
- `data/apps.js`: 미니게임 폴더에 한 줄 추가

## 정한 것과 이유
- 고른 방법과 그 이유. 해 보고 버린 방법이 있으면 버린 이유도 짧게 적습니다.

## 남은 일과 알아 둘 것
- 아직 못 한 것, 확인하지 못한 것, 다른 사람이 건드릴 때 조심할 점
```

반복해서 빠지기 쉬운 함정을 찾았다면 일지와 별도로 레포 루트의 `known-issues.md`에도 한 항목을 추가합니다.
일지는 그날의 이야기이고, known-issues는 다음 사람이 코드를 고치기 전에 꼭 읽는 목록입니다.
